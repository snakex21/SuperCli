# SuperCli 1.0.31

A lighter first request for small-tier and local models, a /resume fix in the
terminal interface, and better measurement tools for evaluations. Polish
notes follow the English ones.

## Before updating

- Back up your portable `supercli-data` directory and close other running
  copies before installing. The updater replaces the two executables, not
  private data, and a manual restart is required afterward.
- No configuration changes are required.

## A lighter first request

Small-tier models (for example gpt-6-luna, gpt-5.4-nano/mini) and models on a
local server (LM Studio, llama.cpp) get a compact tool set. Its first request
still carried the full schemas of the web tools `web_lookup` and `web_fetch`
(about 450 tokens), although in our evaluation transcripts they were 9 of
about 4300 tool calls in project work.

Now:

- `web_lookup` is listed in the on-demand tool catalog instead, one
  `tool_search` away. When your request names the web (a URL, "online",
  "internet", a website, news or the latest facts), that turn carries the
  `web_lookup` contract, and `web_fetch` for a URL, at the end of the request,
  so nothing is lost for web questions and the cached start of the request
  stays the same.
- A download of a direct file URL still carries only `web_download`.
- `ctx_execute` has a shorter description and no 19-digit maximum in its
  schema (very large timeouts are still rejected).
- The chat/advice route and large-tier models on cloud endpoints are
  unchanged.

Measured first request (input tokens reported by the provider):

| model | 1.0.30 | 1.0.31 |
|---|---|---|
| gpt-6-luna (small tier) | ~2800 | ~2390 (-15%) |
| gpt-5.4-nano / gpt-5.4-mini (small tier) | ~2800 | ~2390 (-15%) |
| Qwen 3.8 27B local, LM Studio (local profile) | 4042 | 3470 (-14%) |
| Qwen 3.8 27B via Logfare (large tier, full tools) | ~4760 | ~4730 (unchanged apart from ctx_execute) |

On the local Qwen (Q4_K_M, 32k context, Radeon 7900 XTX) the time to the first
token of an uncached first request went from 4164 ms to 3642 ms (-12.5%,
median of 5). On cloud models the time to first token is dominated by the
model and the network; the medians moved by -0.1 to -0.3 s.

## /resume in the terminal interface

`/resume` set the busy state without refitting the screen, so the transcript
area was one row too tall until the next refresh (the same issue 1.0.30 fixed
for slash and shell commands).

## Evaluation tools

- `supercli-evalsuite` records the size and latency of each run's first model
  request. Its recovery of the usage of timed-out runs now counts the agent's
  own calls (they are journaled as `main`, not `model`).
- `supercli-wireprobe` records the time to first byte and first output, the
  total time and the reported usage of every forwarded request.

## Measurements

Pass rate before -> after (same tasks; gpt-6-luna effort low, 3 repeats;
other models 1 repeat unless noted):

| model | v2 | ho2 | ho3 | v1 |
|---|---|---|---|---|
| gpt-6-luna | 87.0% -> 88.9% | 86.7% -> 86.7% | 100% -> 97.4% | - -> 26/26 |
| gpt-5.4-nano | 63.9% -> 50.0% (2 repeats) | 70% -> 70% | | |
| gpt-5.4-mini | | 70% -> 70% | | |
| Qwen 3.8 27B (Logfare) | 83.3% -> 72.2% | 90% -> 100% | | |
| Qwen 3.8 27B (local) | | 100% -> 100% | | |

The v1 web tasks pass 6/6 with both versions on gpt-6-luna. The nano and
Logfare v2 differences are in tasks that never use web tools (the nano tool
usage is the same in both versions, and a targeted rerun of the four tasks that
flipped gave 3/12 vs 2/12); with one or two repeats on a 16k-window model they
are within the run-to-run spread, but we name them rather than hide them.
ho3 was written by the 1.0.30 audit and is no longer a blind test.

# SuperCli 1.0.31 (PL)

Lżejsze pierwsze zapytanie dla modeli z małego segmentu i modeli lokalnych,
poprawka /resume w interfejsie terminalowym i lepsze narzędzia pomiarowe do
ewaluacji.

## Przed aktualizacją

- Zrób kopię przenośnego katalogu `supercli-data` i zamknij inne uruchomione
  kopie. Aktualizacja podmienia dwa pliki wykonywalne, nie dane prywatne. Po
  instalacji uruchom program ponownie ręcznie.
- Konfiguracja nie wymaga zmian.

## Lżejsze pierwsze zapytanie

Modele z małego segmentu (np. gpt-6-luna, gpt-5.4-nano/mini) i modele na
lokalnym serwerze (LM Studio, llama.cpp) dostają skrócony zestaw narzędzi. Jego
pierwsze zapytanie nadal niosło pełne schematy narzędzi webowych `web_lookup`
i `web_fetch` (ok. 450 tokenów), choć w transkryptach ewaluacji było to 9 z ok.
4300 wywołań narzędzi przy pracy nad projektem.

Teraz:

- `web_lookup` jest w katalogu narzędzi ładowanych na żądanie, jedno
  `tool_search` dalej. Gdy polecenie dotyczy sieci (adres URL, „online”,
  „internet”, strona WWW, wiadomości albo najnowsze informacje), ta tura niesie
  kontrakt `web_lookup`, a przy adresie URL także `web_fetch`, na końcu
  zapytania. Pytania o sieć nic nie tracą, a buforowany początek zapytania się
  nie zmienia.
- Pobieranie bezpośredniego adresu pliku nadal niesie tylko `web_download`.
- `ctx_execute` ma krótszy opis i nie ma w schemacie 19-cyfrowego maksimum
  (bardzo duże limity czasu są nadal odrzucane).
- Trasa czatu/porad i duże modele w chmurze są bez zmian.

Zmierzone pierwsze zapytanie (tokeny wejściowe podane przez dostawcę):

| model | 1.0.30 | 1.0.31 |
|---|---|---|
| gpt-6-luna (mały segment) | ~2800 | ~2390 (-15%) |
| gpt-5.4-nano / gpt-5.4-mini (mały segment) | ~2800 | ~2390 (-15%) |
| Qwen 3.8 27B lokalnie, LM Studio (profil lokalny) | 4042 | 3470 (-14%) |
| Qwen 3.8 27B przez Logfare (duży segment, pełne narzędzia) | ~4760 | ~4730 (bez zmian poza ctx_execute) |

Na lokalnym Qwen (Q4_K_M, kontekst 32k, Radeon 7900 XTX) czas do pierwszego
tokenu niebuforowanego pierwszego zapytania spadł z 4164 ms do 3642 ms
(-12,5%, mediana z 5). W chmurze czas do pierwszego tokenu zależy głównie od
modelu i sieci; mediany zmieniły się o -0,1 do -0,3 s.

## /resume w interfejsie terminalowym

`/resume` ustawiał stan pracy bez ponownego dopasowania ekranu, więc obszar
rozmowy był o jeden wiersz za wysoki do następnego odświeżenia (ten sam błąd,
który 1.0.30 poprawiło dla poleceń z ukośnikiem i poleceń powłoki).

## Narzędzia ewaluacji

- `supercli-evalsuite` zapisuje rozmiar i opóźnienie pierwszego zapytania do
  modelu w każdym przebiegu. Odtwarzanie zużycia przebiegów przerwanych przez
  limit czasu liczy teraz wywołania samego agenta (zapisywane jako `main`, nie
  `model`).
- `supercli-wireprobe` zapisuje czas do pierwszego bajtu i pierwszego
  wyjścia, czas całkowity oraz zgłoszone zużycie każdego przekazanego
  zapytania.

Zdawalność przed -> po (te same zadania; gpt-6-luna, wysiłek low, 3

| gpt-6-luna | 87,0% -> 88,9% | 86,7% -> 86,7% | 100% -> 97,4% | - -> 26/26 |
| gpt-5.4-nano | 63,9% -> 50,0% (2 powtórzenia) | 70% -> 70% | | |
| gpt-5.4-mini | | 70% -> 70% | | |
| Qwen 3.8 27B (Logfare) | 83,3% -> 72,2% | 90% -> 100% | | |
| Qwen 3.8 27B (lokalnie) | | 100% -> 100% | | |

Zadania webowe z v1 przechodzą 6/6 w obu wersjach na gpt-6-luna. Różnice w v2
dla nano i Logfare dotyczą zadań, które w ogóle nie używają narzędzi webowych

jednym lub dwóch powtórzeniach na modelu z oknem 16k mieszczą się w rozrzucie
między przebiegami, ale podajemy je zamiast ukrywać. ho3 napisał audyt 1.0.30,
więc nie jest już testem w ciemno.
