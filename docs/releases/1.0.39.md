# SuperCli 1.0.39 — DRAFT / PLAN (not implemented)

Backlog collected from user feedback after 1.0.38. Theme: **GUI readability,
keep minimalism (no billion options)**. Nothing below is implemented yet.
Polish version follows the English one.

## 1. No English leftovers in translated UIs

Reported: untranslated English strings in the Polish UI (e.g. "pruned").

- Audit every user-visible UI string: locale catalogs, strings built in JS
  (`toast`, `notice`, status lines, tooltips, aria labels) and server texts
  that reach the GUI (notices such as "hid N old message(s) … (pruned)",
  wire `notice` events, setting descriptions).
- Move hard-coded English texts to catalog keys and translate them in all
  27 locales.
- Test: fail when a non-EN locale value is identical to its English value or
  contains English words from a small dictionary, with an allowlist for
  technical terms (model/tool names, `config.toml` keys, units, product
  names). Also scan JS for user-facing string literals outside `t(...)`.

## 2. The "Workers" panel must not block chat scrolling

Reported: the "Agenci pomocniczy" panel creates an invisible rectangle; mouse
wheel / drag over that area does not scroll the chat.

- Find the element that keeps the hit area (collapsed `<details>` with a
  fixed height, an overlay/gradient, a wrapper with `pointer-events`) and make
  only the visible panel interactive; wheel events over the panel forward to
  the transcript when the panel itself cannot scroll.
- Browser test: with the panel collapsed and with a short list, a wheel
  event over the panel's bounding box (and just above it) still scrolls the
  transcript; with a long expanded list the list scrolls first.

## 3. Stopping workers within reach

Stopping sub-agents is currently only possible via tasks / the stall
warning.

- A small stop control on each running worker row (panel) and card, plus
  "Stop all" in the panel header; both ask for confirmation (one dialog,
  listing how many workers stop). No new settings.
- Uses the existing `POST /api/workers {action:"stop"}`; the coordinator
  gets the usual "stopped" notification.
- Browser test: stop one, stop all, cancel the confirmation.

## 4. Readable usage charts ("Usage history")

- Daily tokens: one day dominates the bars. Per-day hover values; consider a
  log-scale toggle; make the cached/uncached stack clearly distinguishable.
- Daily cost: a single spike flattens the rest. Hover values; optional
  cumulative line.
- Donut charts: the grey centre text is hard to read; use the text colour
  and a larger figure.
- TTFT chart is drawn as disconnected segments: show the daily median with a
  p25–p75 band, connected consistently (gaps only for days without data,
  marked as such).
- Empty "Performance telemetry" placeholder: hide it or explain how data
  appears.
- Dataviz practice: one consistent palette, labelled axes with units, hover
  values, legends only where needed; keep it minimal.

# SuperCli 1.0.39 — SZKIC / PLAN (niezaimplementowane)

Lista zadań ze zgłoszeń po 1.0.38. Motyw: **czytelność GUI przy zachowaniu
minimalizmu (bez miliarda opcji)**. Nic z poniższych nie jest jeszcze
zrobione.

## 1. Bez angielskich resztek w przetłumaczonym UI

Zgłoszenie: nieprzetłumaczone angielskie teksty w polskim UI (np. „pruned”).

- Przegląd wszystkich widocznych tekstów: katalogi tłumaczeń, teksty
  składane w JS (`toast`, komunikaty, statusy, podpowiedzi, etykiety aria)
  oraz teksty serwera trafiające do GUI (np. „hid N old message(s) …
  (pruned)”, zdarzenia `notice`, opisy ustawień).
- Przeniesienie zaszytych angielskich tekstów do kluczy katalogu i
  tłumaczenie we wszystkich 27 językach.
- Test: błąd, gdy wartość w języku innym niż EN jest identyczna z angielską
  albo zawiera angielskie słowa z małego słownika; lista wyjątków dla terminów
  technicznych (nazwy modeli/narzędzi, klucze `config.toml`, jednostki, nazwy
  produktów). Dodatkowo skan JS pod kątem tekstów dla użytkownika poza `t(...)`.

## 2. Panel „Agenci pomocniczy” nie może blokować przewijania

Zgłoszenie: panel tworzy niewidoczny prostokąt; kółko myszy / przeciąganie
nad tym obszarem nie przewija rozmowy.

- Znaleźć element trzymający obszar kliknięć (zwinięty `<details>` o stałej
  wysokości, nakładka/gradient, opakowanie z `pointer-events`) i zostawić
  interaktywny tylko widoczny panel; kółko nad panelem przewija transkrypcję,
  gdy sam panel nie ma czego przewijać.
- Test w przeglądarce: przy zwiniętym panelu i krótkiej liście kółko nad
  obszarem panelu (i tuż nad nim) nadal przewija rozmowę; przy długiej
  rozwiniętej liście najpierw przewija się lista.

## 3. Zatrzymywanie agentów pod ręką

Zatrzymanie agenta pomocniczego jest dziś możliwe tylko przez zadania /
ostrzeżenie o braku postępu.

- Mały przycisk stop przy każdym pracującym agencie (panel) i na karcie oraz
  „Zatrzymaj wszystkie” w nagłówku panelu; oba z potwierdzeniem (jedno okno
  z liczbą zatrzymywanych agentów). Bez nowych ustawień.
- Korzysta z istniejącego `POST /api/workers {action:"stop"}`; koordynator
  dostaje zwykłe powiadomienie „zatrzymany”.
- Test w przeglądarce: zatrzymanie jednego, wszystkich, anulowanie.

## 4. Czytelne wykresy („Historia użycia”)

- Dzienne tokeny: jeden dzień dominuje słupki. Wartości po najechaniu;
  rozważyć przełącznik skali logarytmicznej; wyraźnie rozróżnialne warstwy
  cached/uncached.
- Dzienny koszt: pojedynczy szczyt spłaszcza resztę. Wartości po najechaniu;
  opcjonalna linia narastająca.
- Wykresy kołowe: szary tekst w środku jest słabo czytelny; kolor tekstu i
  większa liczba.
- Wykres TTFT rysuje się jako rozłączne odcinki: dzienna mediana z pasmem
  p25–p75, łączona spójnie (przerwy tylko dla dni bez danych, oznaczone).
- Pusty placeholder „Telemetria wydajności”: ukryć albo wyjaśnić, skąd
  pojawią się dane.
- Dobre praktyki wizualizacji: jedna spójna paleta, opisane osie z
  jednostkami, wartości po najechaniu, legendy tylko gdy potrzebne;
  minimalnie.
