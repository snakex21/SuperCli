# SuperCli 1.0.18

Editable assistant replies, single-conversation export/import and a tidier
settings layout.

## Before updating

- Back up your portable `supercli-data` directory and close other running copies
  before installing. The updater replaces the two executables, not private data,
  and a manual restart is required afterward.

## Assistant replies

- Every assistant reply can be copied (⧉). In the TUI, `/copy` copies the last
  reply.
- With `assistant_edit` on (default off), a reply can be edited (✎) and later
  restored to its original text (↶). Edited replies carry a small "edited"
  badge. The original is kept in a separate `message_edits` table.
- `assistant_edit_model_sees` (default off) decides whether the model sees the
  edited text in later turns or keeps working from the original.
- Both settings are available in the GUI and the TUI settings menu.

## Single-conversation export and import

- One conversation can be moved to another SuperCli install and continued
  there, without touching any other data. The file
  (`*.supercli-session.json`) carries the model-visible history (tool calls,
  tool results, inline images) and assistant edits with their originals.
- Import always creates a new conversation with a new ID in the current
  project; nothing is overwritten. Malformed, unsupported or oversized files
  (limit 64 MiB) are rejected.
- Not carried: images stored as separate files (for example screenshots),
  billing records, checkpoints and context summaries.
- GUI: an export icon (⤓) on each conversation in the session list opens a
  "Save as" dialog (falls back to the Downloads folder if unavailable); the Data
  tab has "Import conversation", which opens the imported conversation.
  Import works only from the local machine.
- TUI: `/export session [path]` (or `/export json`) and `/import <path>`, then
  `/resume <id>`. The existing Markdown `/export` and `/export clip` are
  unchanged.

## Settings layout

- The Settings tab is grouped by topic (display and replies, reasoning and
  context, Darwin, verification and access, startup model). Settings that
  belong to agent runs now live only in the Modes tab, so nothing appears
  twice.
- The Modes tab uses the same groups instead of one long list, and three
  context settings now show proper names instead of raw config keys.
- Message merging (`queue_merge`) is an Off/Auto switch like the other
  options instead of a dropdown.
- Keys in `config.toml` are unchanged; only the layout moved.

## Verification

Checked with the full `go test ./...` (including the native-browser UI suite),
`go vet ./...` and README parity for all 27 languages. Export/import is covered
by round-trip tests (messages, edits and metadata match, new ID, existing
sessions untouched), rejection tests and HTTP/TUI command tests, and was tried
by hand in the GUI.
