# SuperCli 1.0.10

This release lets the agent work with desktop programs in the background without taking the mouse, keyboard or focus from the user, and lets the GUI switch projects and sessions while a run continues.

## Desktop programs

- `process_session` starts GUI programs minimized and without focus. Use `visible:true` to show the window.
- Windows: the agent inspects, clicks and types in windows through UI Automation, without moving the mouse or sending keystrokes. A modal or owned window is picked automatically; when it is ambiguous, the windows are listed. Popup menus are included in inspection.
- Screenshots of minimized windows work without a focus change; the window is restored if the capture fails.
- Keyboard focus returns to the user's window during each window action and for 1.5 seconds after it.
- One window action at a time per process.
- A click that closes the program (for example "Don't save") is no longer reported as an error.
- A clear message when a menu cannot be expanded, instead of a silent failure.
- Window and MCP tools no longer ask for consent on every call; `allowed_tools` is still enforced (`confirm_calls` was removed).

## GUI

- Switch project or session while a run continues; each session has its own run gate, and errors of background runs are shown.
- MCP servers per project, with an indicator of running servers.
- Closing the window lets the current work finish in the background.
- Worker activity uses translated tool names and colours; `search_code` results are highlighted and show the matched lines.

## Agent

- The working-directory note is placed after the tool catalog, so the prompt prefix can be reused from cache.
- Codex: `parallel_tool_calls=true` when tools are present.

## Verification and limitations

go test, go vet and the GUI tests passed on Windows; CI passed on Linux. Window automation was checked live on Notepad. The focus can still flicker for 10–30 ms during an action, and a program that takes focus later than 1.5 seconds after an action is not corrected. Closing a program with "Don't save" was checked by unit tests only. Element IDs from `inspect_window` can change between inspections.
