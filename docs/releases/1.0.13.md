# SuperCli 1.0.13

This release adds phone access through a temporary Cloudflare tunnel, keeps the
phone and PC in live sync and lets attachments wait in the message queue.

## Phone access

- The GUI **Phone** button and the TUI `/telefon` command start a temporary
  `trycloudflare.com` tunnel and show a QR code. The phone opens the same GUI
  with the same features as the PC; no extra app is needed.
- `cloudflared` is downloaded automatically on first use (Windows x64), checked
  with SHA256 once and then reused from `supercli-data/tools/cloudflared/`.
- Access is protected by a one-time token and a Host check; the phone keeps a
  7-day cookie. Each tunnel start gives a new address.
- The tunnel closes after 24 hours without a message sent from the phone. Every
  sent message restarts the 24 hours; browsing alone does not.
- A narrow-screen layout keeps the status line (`working • 53.0 s`), header,
  buttons, dialogs and notifications inside the screen width.

## Live sync between devices

- A conversation open on several devices updates live on all of them: user
  messages, streamed answers, tools, commands, workers, questions and Stop.
- The session list updates on every device (new sessions, titles, busy state).
- Command, worker and run timers use the start time recorded by the server, so a
  device that joins later shows the real elapsed time, corrected for clock skew.
- Work no longer depends on the HTTP connection that started it. Turning off the
  phone screen, a sleeping tab or a lost network does not pause the agent; the
  device reattaches or loads the finished answer when it returns. Only Stop or
  closing the program ends a run.
- After the screen wakes up, the conversation scrolls to the bottom if it was at
  the bottom before; a deliberate scroll position is kept.

## Queue

- Messages with images or files can be queued while the agent works. Attachments
  are stored with the queued item, survive a page reload, appear on other
  devices and are sent with the item. The queue shows a 📎 count.

## Configuration

- `--provider codex` without `--base-url` uses the official Codex endpoint.

## Verification

The full Go suite passed on Windows, followed by all UI tests, including new
tests for sync, reconnecting after a disconnect, server-side timestamps,
queued attachments and the phone layout. Phone access, live sync, the screen-off
case and timers were tested by hand on a real phone through the tunnel.
