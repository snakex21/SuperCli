# SuperCli 1.0.25

A security release for the Thunderbird Bridge. Until now SuperCli and the
Thunderbird AI Bridge extension trusted each other through a fixed token that
was the same in every copy, on a fixed port, with CORS open to any page. Any
local program, a second SuperCli or NestCafe, or a web page could take the
port, and Thunderbird attached to whoever held it. During a review a test copy
of NestCafe received the real mailbox connection this way. 1.0.25 replaces the
token with a one-time pairing and signs every message.

The TUI/GUI unification planned for this number moves to 1.0.26.

## Before updating

- **Thunderbird users must update the extension and pair once.** Install
  Thunderbird AI Bridge **0.10.0** (Thunderbird: Add-ons and Themes -> gear ->
  Install Add-on From File), then pair (below). Extension 0.9.x cannot talk to
  1.0.25 and 0.10.0 cannot talk to SuperCli 1.0.24 or older: both sides refuse
  and say which one to update. Nothing is sent to an unpaired or outdated
  side.
- Back up your portable `supercli-data` directory and close other running
  copies before installing. The updater replaces the two executables, not
  private data, and a manual restart is required afterward.

## Pairing Thunderbird

1. In SuperCli open Control panel -> **Thunderbird** -> **Pair** (TUI:
   `/thunderbird pair`). A code such as `K7QM-3XRP-9WTD-HC4N` appears, valid
   for 5 minutes.
2. In Thunderbird open Add-ons and Themes -> **Thunderbird AI Bridge** ->
   **Options**, type the code, click **Pair**.
3. The options page says *Connected*; SuperCli shows *Paired* and
   *Connected*.

Pairing is per SuperCli data folder and per Thunderbird profile. Pairing again
replaces the previous pairing; **Unpair** (GUI) or `/thunderbird unpair`
forgets it, and the extension's options page can remove it on its side.
`/thunderbird` shows the state at any time.

## What changed in the bridge

- **Pairing secret.** The code authenticates an ECDH P-256 exchange; both
  sides derive a 256-bit secret with HKDF-SHA256. An observer of that traffic
  who later sees the code still cannot compute the secret. SuperCli stores it
  in `supercli-data/thunderbird-bridge/pairing.json`, wrapped with DPAPI for
  the current Windows user, in a file and folder only that account can open. A
  data folder copied to another account or machine has to be paired again. The
  code allows 5 wrong attempts and is never logged; neither the code nor the
  secret is ever put in a URL.
- **Mutual authentication.** On every connection SuperCli issues a single-use
  challenge, the extension proves the secret, and SuperCli proves it back.
  The extension sends polls and results only to a host that passed this
  check, so a program that took the port gets nothing and cannot make
  Thunderbird do anything.
- **Signed messages.** Every request (long-poll, result, attachment upload,
  message download) carries an HMAC-SHA256 over method, path, timestamp,
  nonce and body hash; nonces are single use and timestamps must be within
  60 s. Every response is signed too and bound to its request, so an old
  command cannot be replayed.
- **Transport.** Loopback only; the `Host` header must be exactly
  `127.0.0.1:47831`; requests with a web `Origin` are refused; CORS headers
  are sent only for the paired extension (never `*`).
- **Port contention.** An unpaired SuperCli no longer opens the port at all,
  so a test or second copy cannot shadow the paired one. If another instance
  holds the port, SuperCli does not take over; the tool and the status say
  "port 127.0.0.1:47831 is used by another SuperCli instance (name, version,
  pid)" and nothing is sent. It retries when the other instance exits.
- **Status.** The GUI section, `/thunderbird` and NestCafe show paired /
  not paired, connected, the extension version, who holds the port, and why an
  extension was refused (outdated 0.9.x extension, revoked pairing, wrong
  secret). A tool call without pairing fails at once with instructions instead
  of waiting.

Not covered: malware already running as the same Windows user can read both
the Thunderbird profile and the SuperCli data folder. Pairing protects against
other programs, other SuperCli/NestCafe instances and web pages.

## For other hosts

The protocol (`tb-bridge/2`) is documented in `docs/PROTOCOL.md` of the
Thunderbird-AI-Bridge repository, with known-answer vectors shared by the Go
host tests and the extension tests. `GET /api/integrations/thunderbird` now
returns a `bridge` object (`paired`, `connected`, `state`, `message`,
`port_error`, `legacy_extension`, `last_rejected_reason`, ...); `POST
/api/integrations/thunderbird/pair`, `/pair/cancel` and `/unpair` are
local-only.
