# SuperCli 1.0.22

Re-release of 1.0.21 with a fixed release check. The application code is the
same as 1.0.21; see `docs/releases/1.0.21.md` for the web tools, browser tool
and search changes.

## Before updating

- Back up your portable `supercli-data` directory and close other running copies
  before installing. The updater replaces the two executables, not private data,
  and a manual restart is required afterward.

## Why 1.0.21 has no bundles

- The 1.0.21 release workflow stopped at its test step, so no 1.0.21 bundles
  were published. The failing browser check
  (`TestChatGUIStopCommandAndSendUsingProductionJS`) was a race in the
  development-only test proxy (`scripts/ui-checks`), not in SuperCli itself.

## Development

- The native browser checks now forward an in-memory copy of each request body
  through their loopback proxy. Before, a streamed `/api/chat` reply could reach
  the proxy before it finished forwarding the request; net/http had already
  closed the incoming body, the forwarded request failed and the proxy dropped
  the stream before its first event. Chrome then showed "network error". This
  happened now and then on busy Linux CI runners (1.0.20 CI, 1.0.21 release).
  A new test forces that exact ordering, so the check no longer depends on
  timing.
