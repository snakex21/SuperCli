# SuperCli 1.0.14

This release improves terminal rendering, queued-message editing and worker
controls, adds `/skills` and one-command installers, and hardens shared session
and project state.

## Before updating

- Back up your portable `supercli-data` directory and close other running copies
  before installing. The updater replaces the two executables, not private data,
  and a manual restart is required afterward.
- Session-aware housekeeping is now enabled by default. Its first attempt is
  delayed by 30 seconds and it only runs while the portable application is idle.
  Retention may remove old, unreferenced checkpoints and saved snapshots; protected
  or referenced data is retained. To opt out, set `enabled = false` in the
  `[housekeeping]` table of the portable `config.toml`. See
  [the policy and safety limits](../disk-housekeeping.md).

## TUI and Windows drawing

- Correct Windows resize events that report the scrollback buffer dimensions
  instead of the visible console window. This prevents the first-run provider
  picker from appearing blank except for its separator and keyboard footer.
- Preserve ANSI styles when a resize or scroll hides the line that originally
  opened the style, including the shorter viewport caused by a phone keyboard.
- Fit the composer, attachments, keyboard hints and slash suggestions into short
  terminals. The status panel becomes compact and welcome cards use the actual
  conversation area rather than the whole terminal height.
- Keep the suffix and caret of long edited settings visible, and keep wrapped
  selected answers visible in interactive questions.

## Queue, attachments and previews

- Edit queued messages in a large responsive dialog with Save/Cancel, Escape,
  attachment editing and focus restoration. Queue refreshes preserve the draft;
  stale saves cannot edit another project or a dispatched item.
- Add optional queued-message merging and safer claiming, ordering and attachment
  replacement. Queue merging stays off by default.
- Open image previews in a lightbox while retaining lazy media loading.

## Skills, workers and projects

- `/skills` lists and searches project, user and built-in skill metadata locally.
  The GUI opens a paginated browser. Listing does not invoke a model or unpack
  built-in skill instructions.
- Add independent reasoning-effort overrides for task workers, advisors, review
  and Darwin, with inheritance from the main configuration when unset.
- Expose Darwin model and candidate-count controls. Darwin remains off by default,
  candidate count `0` means automatic selection, and automatic merging remains
  off. Mode buttons update immediately and roll back if saving fails.
- Improve worker state/reasoning feedback, preserve conversation history after
  failed or background compaction, and synchronize portable project/MCP state.
  See [project MCP resolution](../project-mcp.md).

## Installation and updating

- Add `install.sh` for Linux, macOS and Termux and `install.ps1` for Windows x64.
  They select a published platform build, verify SHA256, support per-user setup
  and refuse existing destinations rather than overwrite portable data.
- Publish Windows x64, Linux x64/ARM64, Android ARM64 and macOS x64/ARM64 bundles
  together with `SHA256SUMS` and `supercli-update.json`.
- The existing updater remains user-initiated: GUI About or `/update check`,
  `/update download`, `/update install`; CLI `--update` downloads and installs.
  There are no silent background installations. The installation folder must be
  writable. The packaged application does not require Node or Python.

## Stop and connection errors

- Stop no longer passes its successful API response into `AbortController.abort`
  as a rejection reason. Intentional cancellation is shown as stopped, not
  `connection error: undefined`.
- Cancellation belongs to the specific run, so a late rejection from a detached
  run cannot cancel a newer one. Real transport errors remain visible, including
  rejections without an Error object's `message` field.
- Regression checks cover Stop before and during streaming, completion and queue
  handoff, unusual rejection values, failed Stop requests and detached runs.

## Node-free development

- Remove Node, npm, LinkeDOM and Playwright from development tests and scripts.
  UI checks execute native browser JavaScript through a standard-library Go CDP
  driver. Headless Chromium/Chrome/Edge is a development-test requirement, not a
  new application runtime dependency.
- Move README generation and validation to Go, preserving all 27 languages and
  the original documentation checks. `go test ./...` now includes the UI suite.
- CI and release workflows use Git, Go, the native browser and the Go-based GitHub
  CLI directly, with no JavaScript checkout, setup or artifact actions. All six
  portable bundles are verified before the public release is created.

## Verification and known limitation

The release is checked with the full Go suite, `go vet`, 471 native-browser UI
cases (442 preserved, 10 Stop regressions and 19 harness checks), README parity
for all 27 languages, and installer/terminal regression fixtures.
Terminal geometry and color previews use the production renderer; these are not
claims of physical testing on every phone, terminal or operating system.

A reported WebUI painting overlap after expanding a tool block and scrolling to
its end remains unconfirmed. Isolated browser tests, including real wheel events
and nested scroll containers, did not reproduce it. This release does **not**
claim to fix that native-window report.
