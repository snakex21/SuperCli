# SuperCli 1.0.24

Agent runs on hosted models are much cheaper: requests now stay append-only so
the provider's prompt cache covers almost the whole conversation, the first
turn already knows the project layout, and long tool outputs page in fewer
turns. The approval card from 1.0.23 got the polish found in a live
Thunderbird run, and GPT-6 prices are in the cost table.

## Before updating

- Back up your portable `supercli-data` directory and close other running copies
  before installing. The updater replaces the two executables, not private data,
  and a manual restart is required afterward.
- **One-time recompute in the TUI.** The TUI system prompt no longer carries
  the current date (it changed the cached prefix every day; the request tail
  already carries the local date and time). The first request of a TUI session
  you resume after updating therefore re-reads the whole conversation once: a
  single prompt-cache miss on hosted providers, a full prompt evaluation on a
  local llama.cpp/LM Studio server. Later requests are cached as usual.

## Cheaper agent runs

Measured with the bundled agent eval suite (26 tasks, `gpt-6-luna`, effort
low, one run each), 1.0.23 against this release:

| | 1.0.23 | 1.0.24 | change |
|---|---|---|---|
| tasks passed | 25 / 26 | 26 / 26 | +1 |
| suite cost | $0.0477 | $0.0178 | −63% |
| model steps per task | 5.50 | 4.27 | −22% |
| input tokens per task | 26.4k | 18.1k | −31% |
| cached share of input | 46% | 85% | +39 pt |
| uncached input per task | 14.3k | 2.7k | −81% |
| tool errors (suite) | 9 | 6 | −3 |

The largest wins are on long tasks: `long-inventory` $0.0140 → $0.0016 (18 →
6 steps), `rename-across-files` $0.0051 → $0.0013, `long-multi-fix` $0.0102 →
$0.0035. Wall time per task fell from 10.6 s to 9.3 s; time to first token is
unchanged within noise. The long tasks vary from run to run: a sanity run of the
final release build also passed 26/26, at $0.0287 for the suite (79% cached),
with `long-inventory` taking between 7 and 24 steps across runs.

- **Context tail pinning (`context_tail_pinning`).** The request-only trailing
  context (date/time, live snapshots, run hints) used to be rebuilt behind the
  conversation on every request, so no request was ever a prefix of the next
  one and hosted caches only reused the ~2k-token system/tool block. The tail
  now stays where it was first sent while its content is unchanged (the
  minute stamp is ignored and refreshed after 30 minutes); a changed tail
  moves to the end, so every request still carries exactly one tail. The pin
  is never persisted and is dropped on compaction or any history rewrite.
  **On by default for hosted providers**; local llama.cpp-style servers keep
  the old placement, since they reuse the longest common KV prefix anyway.
  To turn it off, add to `config.toml`:

  ```toml
  context_tail_pinning = false
  ```

  `= true` forces it on for a local server as well. The batch
  `--trace-jsonl` context probe reports `tailMove`/`tailMoves` for requests
  that did not resend the previous request as a whole.
- **Project layout in the first turn (layout preflight).** Most coding runs
  started with a `list_dir` round trip. The first-turn repository block now
  includes an ignore-aware layout from the same bounded walk (no extra
  subprocess): every file grouped by folder for a small project (≤ 60 files),
  otherwise the root files and the largest top-level folders with file
  counts, within its own 250-token budget. Used by the batch/TUI coordinator,
  worker briefings and GUI workers.
- **`read_output` paging sized to the model.** Stored tool output used to be
  paged 8 KiB at a time, so a 30 KiB result took four extra model turns. Pages
  are now about 1/16 of the model's context window (between 8 KiB and
  32 KiB); unknown or small windows keep 8 KiB, and the stored-output hint
  offers the same page size.
- **Fewer turns for edits.** The run hint and the `patch_file` description ask
  for one `patch_file` call per file, all in the same turn, with the
  build/test check last. A `read_many` cap error says nothing was read and
  asks for several smaller calls in the same turn instead of a serial retry.
- **Stable system prefix.** The date moved out of the TUI system prompt (see
  "Before updating").

## Approval card polish

- **Exact message ids are resolved.** When `thunderbird_mail` gets
  `message_ids`, the card now shows up to three of those messages (subject,
  sender, date) from a read-only bridge lookup (headers only, never bodies;
  at most 10 ids are checked). If an id is unknown, or lives in another
  folder or account than the request names, the card shows a warning before
  you decide; Thunderbird would refuse such a request anyway. Warnings
  appear in the GUI card and in the TUI prompt.
- **Account names everywhere.** The card description said "in account2"
  while the account row showed the display name. The summary now uses the
  display name too, including folder ids such as `account2://INBOX` and copy
  destinations in another account.
- **A declined approval is reported as declined.** The error the model gets
  now says the user declined the action in SuperCli, nothing was done, the
  tool was never called, and it must not retry. The old "NOT executed"
  wording matched Thunderbird's own refusal text, so models told the user
  "Thunderbird refused". Timeouts and cancelled runs name their reason the
  same way.
- **Translated "outside the workspace" summary.** The description for
  removing a file outside the workspace was English-only; it is now
  translated in all 27 UI languages in the GUI and the TUI.

## Pricing

- GPT-6 prices in the built-in cost table (per 1M tokens, short context, from
  OpenAI's model pages):

  | model | input | cached input | output |
  |---|---|---|---|
  | `gpt-6-luna` | $0.10 | $0.01 | $0.50 |
  | `gpt-6-sol` | $2.00 | $0.20 | $10.00 |
  | `gpt-6.1-sol` | $2.00 | $0.10 | $10.00 |
  | `gpt-6-astra` | $10.00 | $1.00 | $50.00 |

  All four have a 1.05M-token context window and 128k max output, which
  SuperCli reads from the provider catalogs. Prompts over 272k input tokens
  are billed higher by OpenAI (2× input and cache, 1.5× output); the estimate
  uses the short-context rate. ChatGPT/Codex subscription usage is still
  shown as subscription usage, not priced.
