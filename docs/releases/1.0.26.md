# SuperCli 1.0.26

The TUI, the desktop/web GUI and batch mode now share one runtime, local
models (Qwen in LM Studio, llama.cpp, Ollama) reuse the prompt cache across
turns, and both interfaces got the fixes from the UI audit. Polish notes
follow the English ones.

## Before updating

- Back up your portable `supercli-data` directory and close other running
  copies before installing. The updater replaces the two executables, not
  private data, and a manual restart is required afterward.
- No configuration changes are required. The Thunderbird Bridge pairing from
  1.0.25 stays valid.

## One runtime for TUI, GUI and batch

Until now the TUI, the GUI and batch mode each assembled their own tool set,
system prompt, approval gate and agent-loop settings, and the three copies had
started to drift. They now all go through one package (`internal/assembly`),
and each interface is a thin adapter on top of it. Deliberate differences, for
example `ask_user` only where someone can answer, are listed in one table
instead of hiding in three places.

- Behaviour is unchanged: 24 golden snapshots (tool sets, always-on tools,
  schemas, system prompts, loop settings and recorded provider requests for
  every interface and profile) were captured on 1.0.25 and are byte-identical
  after the refactor.
- One bug found on the way is fixed: in the TUI, file edits made through
  `patch_file`, `create_file`, `write_file`, `move` and `copy` did not
  invalidate the code-intelligence cache, so diagnostics could describe the
  old file. The GUI was not affected.

## Local models: prompt cache and context

Measured with qwen3.6-35b-a3b in LM Studio on 9 evaluation tasks, 1.0.25
vs 1.0.26:

| | 1.0.25 | 1.0.26 |
|---|---|---|
| tasks passed | 8/9 | 9/9 |
| follow-up requests that only append to the cached prefix | 0 of 63 | 67 of 72 |
| re-processed prompt tokens per follow-up request (median) | 498 | 1 |
| time to first token on follow-up requests (median) | 0.51 s | 0.29 s |
| wall time, 8 tasks without the longest one | 192 s | 134 s |

- Context-tail pinning, which keeps the changing part of the request at its
  end so the server can reuse everything before it, was off for local servers.
  It is now on for them too.
- SuperCli reads the context length the server has actually loaded
  (llama.cpp `/props`, Ollama `/api/ps`) instead of assuming one.
- LM Studio and Ollama silently cut the middle of a prompt that does not fit.
  SuperCli now notices this, compacts the history instead of sending more cut
  prompts, and if a single turn still does not fit it stops with a message
  saying how to continue: load the model with a larger context, run
  `/compact`, or start a new conversation.
- The small-model system prompt states the read-only tool rule once instead of
  twice (about 4% shorter). Most of the first prompt is tool schemas, which are
  unchanged.
- Trade-off: when the window is nearly full, old tool results are now pruned
  earlier for every provider. On the cloud evaluation this raised the cost of
  the two long 16k-window tasks (lower cache share), while long tasks passed
  more often.

## Interface (UI audit)

- GUI: readable contrast for the Send/Approve buttons, the light theme and
  input borders; the phone-access icon no longer renders as a black box; a six-step type scale instead of 29 hard-coded
  font sizes; status colours mean state (running, done, error,
  waiting for approval, denied), not the kind of tool.
- GUI: a run waiting for your approval says so in the tool row, the composer
  and the status dot instead of looking busy; the approval card has `Y`/`N`/`A`
  shortcuts, a readable operation name and keeps Deny as the default.
- TUI: the approval card is translated, shows operation, target, risk and
  reversibility, uses colour for risk and leaves the end of the conversation
  visible. The read-to-end rule and Deny by default are unchanged.
- TUI: Markdown headings without `#`, aligned tables, quotes and framed code
  blocks with the language; `/diff` is coloured.
- Correct plural forms in all 27 languages (for example "1 narzędzie",
  "4 linie"); notices from the agent loop are translated where a translation
  exists.
- One set of design tokens feeds both the TUI palette and the GUI CSS, with a
  test that catches drift.

## Measurements

Cloud evaluation, gpt-6-luna at reasoning effort low, 3 repeats per suite
(mean ± standard deviation):

| suite | 1.0.25 | 1.0.26 |
|---|---|---|
| v1, 26 tasks: pass rate | 94.9 ± 2.2 % | 98.7 ± 2.2 % |
| v2, 18 harder tasks: pass rate | 61.1 ± 5.6 % | 59.3 ± 6.4 % |
| v1 cost per run | $0.0208 | $0.0239 |
| v2 cost per run | $0.0368 | $0.0391 |

The v1 gain is at the edge of the noise and v2 is unchanged within the noise.
The new v2 suite (medium-size repositories, misleading stack traces, flaky
tests, long sessions, honesty traps) is now part of the repository.

Startup (Windows, median of 2 × 20 runs, alternating builds) is unchanged
within measurement noise: TUI welcome screen about 159 ms, GUI ready about
572 ms, `--version` 44-54 ms in both versions.

# SuperCli 1.0.26 (PL)

TUI, GUI (desktop/web) i tryb wsadowy korzystają teraz z jednego wspólnego
runtime'u. Modele lokalne (Qwen w LM Studio, llama.cpp, Ollama) ponownie
używają cache'u promptu między turami, a oba interfejsy dostały poprawki z
audytu UI.

## Przed aktualizacją

- Zrób kopię przenośnego katalogu `supercli-data` i zamknij inne uruchomione
  kopie. Aktualizacja podmienia dwa pliki wykonywalne, nie dane prywatne. Po
  instalacji uruchom program ponownie ręcznie.
- Konfiguracja nie wymaga zmian. Parowanie Thunderbird Bridge z 1.0.25 jest
  nadal ważne.

## Jeden runtime dla TUI, GUI i trybu wsadowego

Dotąd TUI, GUI i tryb wsadowy osobno składały zestaw narzędzi, prompt
systemowy, bramkę zgody i ustawienia pętli agenta, a trzy kopie zaczęły się
rozjeżdżać. Teraz wszystkie przechodzą przez jeden pakiet
(`internal/assembly`), a każdy interfejs jest cienką nakładką. Celowe różnice,
np. `ask_user` tylko tam, gdzie ktoś może odpowiedzieć, są w jednej tabeli.

- Zachowanie się nie zmieniło: 24 snapshoty (zestawy narzędzi, narzędzia
  zawsze włączone, schematy, prompty systemowe, ustawienia pętli i nagrane
  żądania do dostawcy dla każdego interfejsu i profilu) zapisane na 1.0.25 są
  po refaktorze identyczne bajt w bajt.
- Naprawiony błąd znaleziony przy okazji: w TUI edycje przez `patch_file`,
  `create_file`, `write_file`, `move` i `copy` nie unieważniały cache'u analizy
  kodu, więc diagnostyka mogła opisywać starą wersję pliku. GUI tego błędu nie
  miało.

## Modele lokalne: cache promptu i kontekst

Pomiar na qwen3.6-35b-a3b w LM Studio, 9 zadań ewaluacyjnych, 1.0.25 vs 1.0.26:

| | 1.0.25 | 1.0.26 |
|---|---|---|
| zaliczone zadania | 8/9 | 9/9 |
| kolejne żądania, które tylko dopisują do prefiksu w cache'u | 0 z 63 | 67 z 72 |
| ponownie przeliczane tokeny promptu na kolejne żądanie (mediana) | 498 | 1 |
| czas do pierwszego tokena przy kolejnych żądaniach (mediana) | 0,51 s | 0,29 s |
| czas 8 zadań bez najdłuższego | 192 s | 134 s |

- Przypinanie ogona kontekstu (zmienna część żądania zostaje na końcu, więc
  serwer może użyć ponownie wszystkiego przed nią) było wyłączone dla serwerów
  lokalnych. Teraz działa i dla nich.
- SuperCli odczytuje długość kontekstu faktycznie załadowaną przez serwer
  (llama.cpp `/props`, Ollama `/api/ps`), zamiast ją zakładać.
- LM Studio i Ollama po cichu wycinają środek promptu, który się nie mieści.
  SuperCli to wykrywa i kompaktuje historię, zamiast wysyłać kolejne ucięte
  prompty. Jeśli pojedyncza tura nadal się nie mieści, zatrzymuje się z
  komunikatem, co zrobić: załadować model z większym kontekstem, użyć
  `/compact` albo zacząć nową rozmowę.
- Prompt systemowy dla małych modeli podaje regułę narzędzi tylko do odczytu
  raz zamiast dwa razy (około 4% krótszy). Większość pierwszego promptu to
  schematy narzędzi, które się nie zmieniły.
- Kompromis: przy prawie pełnym oknie stare wyniki narzędzi są teraz
  przycinane wcześniej, dla każdego dostawcy. W ewaluacji w chmurze podniosło
  to koszt dwóch długich zadań z oknem 16k (mniejszy udział cache'u), a długie
  zadania częściej przechodziły.

## Interfejs (audyt UI)

- GUI: czytelny kontrast przycisków Wyślij/Zatwierdź, motywu jasnego i ramek
  pól; ikona dostępu z telefonu nie jest już czarnym prostokątem; sześciostopniowa skala
  czcionek zamiast 29 wpisanych na sztywno rozmiarów; kolory oznaczają stan (pracuje, gotowe, błąd, czeka na
  zgodę, odrzucono), a nie rodzaj narzędzia.
- GUI: przebieg czekający na Twoją zgodę mówi o tym w wierszu narzędzia, w
  polu wiadomości i w kropce statusu, zamiast udawać pracę. Karta zgody ma
  skróty `Y`/`N`/`A`, czytelną nazwę operacji i nadal domyślnie „Odrzuć”.
- TUI: karta zgody jest przetłumaczona, pokazuje operację, obiekt, ryzyko i
  odwracalność, koloruje ryzyko i zostawia widoczny koniec rozmowy. Reguła
  „przeczytaj do końca” i domyślne „Odrzuć” bez zmian.
- TUI: nagłówki Markdown bez `#`, wyrównane tabele, cytaty i bloki kodu w
  ramce z nazwą języka; kolorowy `/diff`.
- Poprawne formy liczby mnogiej w 27 językach (np. „1 narzędzie”, „4 linie”);
  komunikaty pętli agenta są tłumaczone tam, gdzie istnieje tłumaczenie.
- Jeden zestaw tokenów projektowych zasila paletę TUI i CSS GUI, a test
  wychwytuje rozjazd.

## Pomiary

Ewaluacja w chmurze, gpt-6-luna z reasoning effort low, 3 powtórzenia na
zestaw (średnia ± odchylenie standardowe):

| zestaw | 1.0.25 | 1.0.26 |
|---|---|---|
| v1, 26 zadań: zaliczone | 94,9 ± 2,2 % | 98,7 ± 2,2 % |
| v2, 18 trudniejszych zadań: zaliczone | 61,1 ± 5,6 % | 59,3 ± 6,4 % |
| koszt przebiegu v1 | 0,0208 $ | 0,0239 $ |
| koszt przebiegu v2 | 0,0368 $ | 0,0391 $ |

Wzrost w v1 jest na granicy szumu, a v2 bez zmian w granicach szumu. Nowy
zestaw v2 (średniej wielkości repozytoria, mylące stack trace'y, flaky testy,
długie sesje, pułapki uczciwości) jest teraz częścią repozytorium.

Czas startu (Windows, mediana z 2 × 20 uruchomień, na przemian obie wersje)
bez zmian w granicach szumu: ekran powitalny TUI około 159 ms, gotowość GUI
około 572 ms, `--version` 44-54 ms w obu wersjach.
