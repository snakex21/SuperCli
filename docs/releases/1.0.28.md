# SuperCli 1.0.28

The agent no longer invents things. When a request names a config key, a
function, a file or a flag that does not exist, SuperCli now notices before
editing: it does the rest of the request, says exactly what is missing and
asks, instead of adding the key or quietly changing a similarly named
function. Provider retries are now configurable (including "until it
works"), and rate limits reported inside the response stream (Cloudflare
Workers AI, Logfare and other gateways) are retried instead of failing the
request. Polish notes follow the English ones.

## Before updating

- Back up your portable `supercli-data` directory and close other running
  copies before installing. The updater replaces the two executables, not
  private data, and a manual restart is required afterward.
- No configuration changes are required. The new keys below all have
  defaults that keep the current behaviour, except that a temporary 503 is
  now retried 5 times after the first attempt (6 calls instead of 5).

## Verify before use

- **Name check.** At the start of a project request, SuperCli looks up the
  code-like names the request mentions (backticked names, `snake_case` and
  `camelCase` identifiers, `name()`, `--flags`, dotted keys, paths with an
  extension) in the workspace with one bounded scan (4000 files, 400 ms, the
  usual ignore list). It makes no model call. The names that exist nowhere
  are listed for the model, together with similar existing names, and with
  the rule: do every other part, do not add, define or wire up the missing
  name, do not apply that part to a look-alike, then say what was not found
  and ask.
- Names the request asks to create ("add a `--verbose` flag", "rename X to
  Y", "a helper named ...") are not checked. Neither are literal values
  ("the line `none`", "ends with `Admin`"), globs, code blocks or SuperCli's
  own tool names. When the workspace is too large to scan within the limits,
  the check stays silent rather than guess.
- `name_check = false` turns it off.

## Exact numbers come from a script

A request that asks for exact counts, totals, percentiles, top-N lists, long
sorted tables or dependency cycles gets one extra line in the request tail:
compute them with a short `ctx_execute` script instead of tallying by hand.
`compute_hint = false` turns it off.

## Provider retries, "ignore errors" and request limits

- **`max_retries`** (default 5) controls how often a temporary provider error
  is retried: HTTP 429/5xx/529, "overloaded", dropped connections, and rate
  limits reported inside the stream. `0` means never. `-1` (also `"inf"`)
  means retry until it works or you stop the run. Waits use Retry-After
  (header or error body) or exponential backoff with jitter, capped at 60 s.
  A per-minute limit without Retry-After waits long enough to reach the next
  minute. The status line shows "retry 3/5" or "retry 12/∞".
  Ctrl+C/Esc in the TUI, Stop in the GUI and the batch-mode signal cancel
  immediately.
- **`retry_unknown_errors`** (default off) also retries provider errors
  SuperCli does not recognise. Errors that cannot succeed on a retry are
  never retried, whatever the settings: authentication (401/403), invalid
  request (400), unknown model (404), context overflow, and used-up daily or
  billing quotas.
- **`requests_per_minute`** (default 0, off) caps how many requests
  SuperCli itself starts per minute to one provider endpoint. The cap is
  shared by all parallel workers and side calls. Set it globally or per
  `[[providers]]` entry. One SuperCli process with parallel workers can
  exceed a gateway's per-minute quota on its own, even when your account as
  a whole is far from its limit.
- All three settings are in TUI `/settings` (Context), GUI Settings
  (Verification, access and fallback) and `config.toml`, in all 27
  languages. NestCafe's embedded engine reads the same keys from the same
  config.
- **Gateways (Cloudflare Workers AI, Logfare and other OpenAI-compatible
  custom providers).** Cloudflare's `{"errors":[{code,message}]}` bodies are
  now read, both as HTTP errors and inside the stream.
  - Capacity, timeout and per-minute errors are retried.
  - Daily-allocation and plan errors are reported at once.
  - The model list skips image, audio and embedding entries and shows which
    models support tools.
  - A model that rejects the `tools` field keeps working without tools, with
    a notice.

## Runs that used to end empty

- When the request no longer fits the context window even after compaction,
  SuperCli first prunes every older tool result once and retries. If it
  still does not fit, the final answer says that it had to stop, which files
  this request had already changed, and how to continue. Before, the answer
  was empty.
- The runaway guard stops a tool call whose arguments turn into endless
  whitespace. The call is now requested again, up to twice per request, with
  a note to split large edits, instead of ending the request.
- `read_many` with a glob that matches more than 12 files reads the first 12
  and lists the rest, instead of failing. `search_code` accepts a
  comma-separated `include` (`*.go,*.py`).

## Measurements

Cloud evaluation, gpt-6-luna at reasoning effort low, mean ± standard
deviation over repeats. 1.0.27 was re-measured on the corrected suites, so
both columns use the same graders.

| suite | 1.0.27 | 1.0.28 |
|---|---|---|
| v1, 26 tasks (3 repeats): pass rate | 97.4 ± 2.2 % | 100.0 ± 0.0 % |
| v2, 18 tasks (6 repeats): pass rate | 88.0 ± 4.2 % | 88.0 ± 6.5 % |
| v2: mean score | 0.899 ± 0.024 | 0.936 ± 0.044 |
| ho2, 10 new held-out tasks (3 repeats): pass rate | 70.0 ± 0.0 % | 93.3 ± 5.8 % |
| ho2 honesty tasks (3 × 3 runs) | 3/9 | 9/9 |
| v1 cost per repeat | $0.0230 | $0.0254 |
| v2 cost per repeat | $0.0374 | $0.0381 |
| ho2 cost per repeat | $0.0149 | $0.0155 |

- **ho2** is a new held-out suite of 10 hard tasks
  (`test/go/eval/agent-suite-ho2.json`): a missing environment variable,
  function or file next to a similar real one, similar-name traps,
  multi-file refactors in Go/Python/JavaScript, long-context debugging and a
  partial-information task. A separate author wrote it before any 1.0.28
  code existed, and it was never used for tuning.
- **v2:** `v2-parallel-service-audit` went from 0/6 to 6/6 (it now computes
  dependency cycles with a script) and `v2-py-long-routes` from 4/6 to 6/6.
  `v2-ts-rename-field` (5/6 → 2/6) and `v2-py-misleading-trace` (5/6 → 3/6)
  dropped. None of the new mechanisms fires on those two tasks, and the
  failing runs follow the same steps as the passing ones, so we read this as
  model noise. The pass rate is therefore unchanged and the mean score is
  higher.
- **Suite corrections, applied to both columns.**
  - The `v2-big-log-incident` log was never committed (`.gitignore`).
  - The `v2-ts-rename-field` grader rejected valid solutions that kept a
    `userId` function parameter.
  - Answer checks did not accept typographic apostrophes (isn’t).
  - Parallel repeats of one task could share a workspace.
- **Dropped:**
  - A "scope check" that sent "nothing else" requests back to review changed
    files outside the list. It showed no gain on top of the name check and
    cost 13-20 % more.
  - A repeated-pattern runaway guard, which would have flagged a legitimate
    file of identical lines that an existing test protects.
  - Raising reasoning effort automatically for hard tasks: the 1.0.27
    diagnostic measured no gain worth the 50-60 % higher cost.

# SuperCli 1.0.28 (PL)

Agent przestał zmyślać. Gdy polecenie wymienia klucz konfiguracji, funkcję,
plik albo flagę, których nie ma, SuperCli zauważa to przed edycją: robi resztę
polecenia, mówi dokładnie, czego brakuje, i pyta. Nie dopisuje klucza ani po
cichu nie zmienia funkcji o podobnej nazwie. Liczbę ponowień po błędach
dostawcy można teraz ustawić (także „do skutku”). Limity zapytań zgłaszane w
strumieniu odpowiedzi (Cloudflare Workers AI, Logfare i inne bramki) są
ponawiane, zamiast przerywać polecenie.

## Przed aktualizacją

- Zrób kopię przenośnego katalogu `supercli-data` i zamknij inne uruchomione
  kopie. Aktualizacja podmienia dwa pliki wykonywalne, nie dane prywatne. Po
  instalacji uruchom program ponownie ręcznie.
- Konfiguracja nie wymaga zmian. Nowe klucze mają wartości domyślne
  zachowujące dotychczasowe działanie. Jedyna różnica: chwilowy błąd 503 jest
  teraz ponawiany 5 razy po pierwszej próbie (6 wywołań zamiast 5).

## Sprawdź, zanim użyjesz

- **Sprawdzanie nazw.** Na początku polecenia projektowego SuperCli szuka w
  workspace nazw kodowych, które polecenie wymienia (nazwy w backtickach,
  identyfikatory `snake_case` i `camelCase`, `nazwa()`, `--flagi`, klucze z
  kropką, ścieżki z rozszerzeniem). Robi to jednym ograniczonym przeszukaniem
  (4000 plików, 400 ms, zwykła lista pominięć) i bez wywołania modelu. Nazwy,
  których nie ma nigdzie, trafiają do modelu razem z podobnymi istniejącymi
  nazwami i z regułą: zrób wszystkie pozostałe części, nie dodawaj, nie
  definiuj i nie podłączaj brakującej nazwy, nie stosuj tej części do nazwy
  podobnej, a na końcu powiedz, czego nie znaleziono, i zapytaj.
- Nazwy, które polecenie każe utworzyć („dodaj flagę `--verbose`”, „zmień
  nazwę X na Y”), nie są sprawdzane. Nie są też sprawdzane wartości
  dosłowne, wzorce glob, bloki kodu ani nazwy narzędzi SuperCli. Gdy
  workspace jest za duży, by przeszukać go w limitach, sprawdzanie milczy
  zamiast zgadywać.
- `name_check = false` je wyłącza.

## Dokładne liczby ze skryptu

Polecenie, które prosi o dokładne liczby, sumy, percentyle, listy top-N,
długie posortowane tabele albo cykle zależności, dostaje jedną dodatkową
linię w końcówce zapytania: policz to krótkim skryptem `ctx_execute`, nie
ręcznie. `compute_hint = false` ją wyłącza.

## Ponowienia, „ignorowanie błędów” i limit zapytań

- **`max_retries`** (domyślnie 5) określa, ile razy ponawiany jest chwilowy
  błąd dostawcy: HTTP 429/5xx/529, „overloaded”, zerwane połączenie oraz
  limit zapytań zgłoszony w strumieniu. `0` oznacza nigdy, a `-1` (także
  `"inf"`) ponawianie do skutku albo do zatrzymania.
  - Odczekanie uwzględnia Retry-After (z nagłówka lub z treści błędu) albo
    wykładniczy backoff z losowym rozrzutem, maksymalnie 60 s.
  - Limit minutowy bez Retry-After czeka do następnej minuty.
  - Status pokazuje „ponowienie 3/5” albo „ponowienie 12/∞”.
  - Ctrl+C/Esc w TUI, Stop w GUI i sygnał w trybie batch przerywają
    natychmiast.
- **`retry_unknown_errors`** (domyślnie wyłączone) ponawia także błędy
  dostawcy, których SuperCli nie rozpoznaje. Nigdy nie są ponawiane, bez
  względu na ustawienia: błędy uwierzytelnienia (401/403), błędne żądanie
  (400), nieznany model (404), przepełnienie kontekstu oraz wyczerpany limit
  dzienny lub rozliczeniowy.
- **`requests_per_minute`** (domyślnie 0, wyłączone) ogranicza, ile zapytań
  na minutę SuperCli sam wysyła do jednego dostawcy. Limit jest wspólny dla
  wszystkich równoległych workerów i wywołań pobocznych. Można go ustawić
  globalnie albo w pozycji `[[providers]]`. Jeden proces SuperCli z
  równoległymi workerami może sam przekroczyć minutowy limit bramki, nawet
  gdy konto jest daleko od swojego limitu.
- Wszystkie trzy ustawienia są w TUI `/settings` (Kontekst), w Ustawieniach
  GUI (Weryfikacja, dostęp i fallback) i w `config.toml`, we wszystkich 27
  językach. Wbudowany silnik NestCafe czyta te same klucze z tej samej
  konfiguracji.
- **Bramki (Cloudflare Workers AI, Logfare i inni niestandardowi dostawcy
  zgodni z OpenAI).** Błędy w formacie Cloudflare
  `{"errors":[{code,message}]}` są teraz odczytywane zarówno jako błędy HTTP,
  jak i w strumieniu.
  - Błędy przeciążenia, przekroczenia czasu i limitu minutowego są
    ponawiane.
  - Wyczerpany przydział dzienny i błędy planu są zgłaszane od razu.
  - Lista modeli pomija modele obrazów, audio i embeddingów oraz pokazuje,
    które modele obsługują narzędzia.
  - Model, który odrzuca pole `tools`, działa dalej bez narzędzi, z
    komunikatem.

## Przebiegi, które kończyły się pustą odpowiedzią

- Gdy zapytanie nie mieści się w oknie kontekstu nawet po kompakcji,
  SuperCli najpierw raz przycina wszystkie starsze wyniki narzędzi i ponawia
  zapytanie. Jeśli nadal się nie mieści, odpowiedź końcowa mówi, że praca
  została przerwana, które pliki polecenie już zmieniło i jak kontynuować.
  Wcześniej odpowiedź była pusta.
- Zabezpieczenie przed wywołaniem narzędzia, którego argumenty zamieniają się
  w niekończące się białe znaki, prosi teraz o ponowne wysłanie wywołania
  (najwyżej dwa razy na polecenie, z radą, by podzielić dużą edycję).
  Wcześniej kończyło polecenie.
- `read_many` ze wzorcem obejmującym ponad 12 plików czyta pierwsze 12 i
  wymienia resztę, zamiast zwracać błąd. `search_code` przyjmuje `include`
  rozdzielony przecinkami (`*.go,*.py`).

## Pomiary

Ewaluacja w chmurze, gpt-6-luna z reasoning effort low, średnia ± odchylenie
standardowe z powtórzeń. 1.0.27 zmierzono ponownie na poprawionych
zestawach, więc obie kolumny mają te same gradery.

| zestaw | 1.0.27 | 1.0.28 |
|---|---|---|
| v1, 26 zadań (3 powt.): zaliczone | 97,4 ± 2,2% | 100,0 ± 0,0% |
| v2, 18 zadań (6 powt.): zaliczone | 88,0 ± 4,2% | 88,0 ± 6,5% |
| v2: średni wynik | 0,899 ± 0,024 | 0,936 ± 0,044 |
| ho2, 10 nowych zadań held-out (3 powt.): zaliczone | 70,0 ± 0,0% | 93,3 ± 5,8% |
| zadania uczciwości w ho2 (3 × 3 przebiegi) | 3/9 | 9/9 |
| koszt powtórzenia v1 | 0,0230 $ | 0,0254 $ |
| koszt powtórzenia v2 | 0,0374 $ | 0,0381 $ |
| koszt powtórzenia ho2 | 0,0149 $ | 0,0155 $ |

- **ho2** to nowy zestaw held-out z 10 trudnymi zadaniami
  (`test/go/eval/agent-suite-ho2.json`): brakująca zmienna środowiskowa,
  funkcja albo plik obok podobnej istniejącej, pułapki podobnych nazw,
  refaktory wielu plików w Go/Pythonie/JavaScripcie, debugowanie przy długim
  kontekście i zadanie z niepełną informacją. Napisał go osobny autor, zanim
  powstał jakikolwiek kod 1.0.28, i nie był używany do strojenia.
- **v2:** `v2-parallel-service-audit` wzrosło z 0/6 do 6/6 (cykle zależności
  są teraz liczone skryptem), a `v2-py-long-routes` z 4/6 do 6/6. Spadły
  `v2-ts-rename-field` (5/6 → 2/6) i `v2-py-misleading-trace` (5/6 → 3/6).
  Żaden nowy mechanizm nie uruchamia się w tych dwóch zadaniach, a
  niezaliczone przebiegi wykonują te same kroki co zaliczone, więc traktujemy
  to jako szum modelu. Odsetek zaliczonych jest więc bez zmian, a średni
  wynik wyższy.
- **Poprawki zestawów, zastosowane w obu kolumnach.**
  - Log zadania `v2-big-log-incident` nigdy nie trafił do repozytorium
    (`.gitignore`).
  - Grader `v2-ts-rename-field` odrzucał poprawne rozwiązania, które
    zostawiały parametr funkcji `userId`.
  - Sprawdzanie odpowiedzi nie akceptowało typograficznego apostrofu (isn’t).
  - Równoległe powtórzenia jednego zadania mogły dzielić workspace.
- **Odrzucone:**
  - „Kontrola zakresu”, która przy poleceniach „nic więcej” kazała
    przejrzeć zmienione pliki spoza listy. Nie dała zysku ponad sprawdzanie
    nazw, a kosztowała 13-20% więcej.
  - Wykrywanie powtarzającego się wzorca w argumentach narzędzi, bo
    zatrzymałoby legalny plik z identycznymi liniami, który chroni istniejący
    test.
  - Automatyczne podnoszenie reasoning effort przy trudnych zadaniach:
    diagnostyka 1.0.27 nie wykazała zysku wartego 50-60% wyższego kosztu.
