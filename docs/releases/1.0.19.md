# SuperCli 1.0.19

MCP 2: faster, cheaper MCP that stays fully compatible with plain MCP servers,
plus correct context windows for Cline models.

## Before updating

- Back up your portable `supercli-data` directory and close other running copies
  before installing. The updater replaces the two executables, not private data,
  and a manual restart is required afterward.

## Cline

- Cline models show their real context window (for example about 1M) as soon
  as the model is selected, instead of a temporary `~128k` until the first
  request. Cline's model list carries no window sizes, so they are taken from
  the public OpenRouter catalog (no key needed). Manual overrides still win.
- Reasoning effort is sent correctly to `api.cline.bot`.
- A rescan no longer drops an already known context window.

## MCP 2

Plain MCP servers work unchanged. Extras are optional and use MCP `_meta`
(`supercli/` keys) or the portable `manifest.toml`, so other clients ignore
them. Details: `docs/mcp2.md`.

- **Images and files from MCP** are saved to session media and shown as a
  collapsed thumbnail, like screenshots. A new setting "MCP images" (Settings →
  MCP) has three modes: for the model (default, as before), preview only (the
  model gets just the path, no image tokens) and file only. It can also be set
  per server in `config.toml` or the manifest. Preview thumbnails survive
  reopening a conversation.
- **Resource links and embedded resources** are supported; binary content is
  saved as a file and the model gets its path.
- **Large results** keep their full text; the model gets a summary and can read
  the rest with `read_output` instead of losing the middle.
- **Batch calls**: `mcp_bridge` accepts up to 8 calls in one request, run in
  order; one failing call does not stop the others.
- **Tools declared in the manifest** are searchable without starting the
  server; it starts only when a tool is called.
- **Read-only hints** (`readOnlyHint`, manifest `read_only`) let such tools run
  in parallel with other read-only tools.
- **Progress and Stop**: server progress is shown on the tool card (GUI) and
  status bar (TUI); Stop sends a real cancellation to the server.
- **Per-conversation sessions**: a server with `session = "conversation"`
  receives the conversation id to keep its own state.

## Verification

Checked with `go build ./...`, `go vet ./internal/...` and `go test` for the
llm, tools, agent, webgui, config, session-storage, TUI and native-browser UI
packages. New tests cover catalog enrichment, image modes, resources, large
results, batch calls, manifest tools, read-only hints, progress/cancel,
sessions and preview restore. Cline windows and the MCP image setting were
checked by hand in the GUI.
