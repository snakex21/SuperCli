# SuperCli 1.0.36

Follow-up fixes for 1.0.35: a calmer "Jump to latest" button and worker cards
that always show a definite state. Polish notes follow the English ones.

## Before updating

- Back up your portable `supercli-data` directory and close other running
  copies before installing. The updater replaces the two executables, not
  private data, and a manual restart is required afterward.
- No configuration changes are required.

## "Jump to latest" is moderate again

1.0.35 made the button a large orange pill that covered the transcript. It
keeps the filled accent colour and its contrast (>= 4.5:1 in every theme), but
is now body-text size, about 30 px tall, with compact padding and a small
shadow: clearly visible, no longer dominant.

## Worker cards: no more "Status unconfirmed" for a working agent

Reported: "Worker 8 · code" showed "Status unconfirmed" and "No tool activity
recorded for this run" while the badge said "1 in background". The saved data
showed the worker really was working (21 minutes, 16 steps, 31 tool calls; it
finished and reported back on its own). The card was the problem:

- After a turn ended, the transcript rebuilt the card from saved history. A
  card from history has no run number, and the 3-second status check refused
  to match a run-less card with the server's worker ("unversioned run"), marked
  it unconfirmed and stopped checking it. Fixed: the server now tells which
  conversation a worker belongs to; for this conversation's own worker the
  card adopts the server's run and state (working / queued / done / failed /
  stopped / interrupted). Live progress bound to the card also establishes its
  run. A card rebuilt from history of a still-working agent says so instead of
  "no tool activity recorded".
- Network errors no longer stop the status check for good; it backs off up to
  30 s and recovers.
- Workers of another conversation that happen to share an id are ignored both
  in the GUI and in the restart reconciliation.

## Every worker has a definite state

- A worker whose first run could not begin (canceled, checkpoint binding
  refused, ...) used to stay "created" forever: counted as active, holding a
  worker slot, shown as running. It is now **failed** with the reason
  ("did not start: ..."), saved, and the coordinator receives the failure
  report (automatic wake-up). **Resume** retries it with its original task.
- The worker's own first run waits for a briefly held run lock (a concurrent
  `send_message`) instead of failing and stranding the worker.
- The saved worker record says "running" while the worker runs (it said
  "created", runs=0 until the end of the run).
- A worker that waits to start is shown as "queued (waiting to start)".
- The "N in background" badge counts only workers whose runner is alive.

## Tests

New tests cover a never-started worker becoming failed with its reason, its
resume with the original task, the coordinator being notified of a start
failure, the first run waiting for a briefly held run lock, `send_message` to a
queued worker, a running worker saved as running, restart reconciliation
ignoring a same-id worker of another conversation, a worker spawned during a
wake-up turn, and in the browser: a card rebuilt from history adopting the
server's run and state, foreign-conversation workers being ignored, status
checks recovering after network errors, the queued label, and the moderate
size of "Jump to latest".

# SuperCli 1.0.36 (PL)

Poprawki do 1.0.35: spokojniejszy przycisk „Przejdź do najnowszych" i karty
agentów, które zawsze pokazują określony stan.

## Przed aktualizacją

- Zrób kopię przenośnego katalogu `supercli-data` i zamknij inne uruchomione
  kopie. Aktualizacja podmienia dwa pliki wykonywalne, nie dane prywatne. Po
  instalacji uruchom program ponownie ręcznie.
- Konfiguracja nie wymaga zmian.

## Przycisk „Przejdź do najnowszych" znów umiarkowany

W 1.0.35 przycisk stał się dużą pomarańczową pigułką zasłaniającą rozmowę.
Zachowuje wypełnienie kolorem akcentu i kontrast (>= 4,5:1 w każdym motywie),
ale ma rozmiar tekstu rozmowy, ok. 30 px wysokości, zwarte marginesy i mały
cień: dobrze widoczny, ale nie dominuje.

## Karty agentów: koniec „Status niepotwierdzony" dla pracującego agenta

Zgłoszenie: „Worker 8 · code" pokazywał „Status niepotwierdzony" i „Brak
zapisu aktywności narzędzi", a znaczek „1 w tle". Zapisane dane pokazały, że
agent naprawdę pracował (21 minut, 16 kroków, 31 wywołań narzędzi; sam
skończył i zgłosił wynik). Winna była karta:

- Po zakończeniu tury rozmowa odbudowywała kartę z historii. Karta z historii
  nie ma numeru przebiegu, a sprawdzanie stanu co 3 s odmawiało dopasowania jej
  do agenta z serwera, oznaczało ją jako niepotwierdzoną i przestawało ją
  sprawdzać. Naprawione: serwer podaje, do której rozmowy należy agent; dla
  agenta tej rozmowy karta przyjmuje przebieg i stan z serwera (pracuje / w
  kolejce / gotowe / błąd / zatrzymano / przerwany). Postęp na żywo powiązany
  z kartą też ustala przebieg. Karta odbudowana z historii dla pracującego
  agenta mówi, że pracuje, zamiast „brak zapisu aktywności".
- Błędy sieci nie zatrzymują już sprawdzania na stałe (ponawianie do 30 s).
- Agenci innej rozmowy o tym samym id są pomijani w GUI i przy uzgadnianiu po
  restarcie.

## Każdy agent ma określony stan

- Agent, którego pierwszy przebieg nie mógł się zacząć, zostawał na zawsze
  „created": liczony jako aktywny, zajmował miejsce i wyglądał na pracującego.
  Teraz ma stan **błąd** z powodem („did not start: …"), jest zapisany, a
  koordynator dostaje zgłoszenie błędu (automatyczna tura). **Wznów** ponawia
  go z pierwotnym zadaniem.
- Pierwszy przebieg agenta czeka na krótko zajętą blokadę (równoległe
  `send_message`) zamiast kończyć się błędem i porzucać agenta.
- Zapis agenta mówi „running" w trakcie pracy (wcześniej „created", runs=0 do
  końca przebiegu).
- Agent czekający na start ma etykietę „w kolejce (czeka na start)".
- Znaczek „N w tle" liczy tylko agentów, których proces naprawdę działa.
