# SuperCli 1.0.12

This release makes image requests more reliable, hides attachment markers from
conversation text, gives the TUI the same colours as the GUI and keeps recent
user requests after context compaction.

## Images

- A rejected image no longer disables images for the rest of the session. Each
  request decides again, so switching to a vision model works without a restart.
- When an image cannot be sent, the model receives an honest placeholder instead
  of pretending the image is present.
- Image rejections are logged with the model and HTTP status
  (`vision: model=… http …`), which makes provider problems easier to diagnose.
- Attachment instructions tell the model that the image is already in the
  message, so it answers directly instead of searching folders or running
  commands to find the file.

## Attachments

- `📎 file` markers are hidden in conversation titles, the session list, resume,
  memory and the GUI message bubble. The GUI shows attached files as tiles and
  the TUI shows a short `[pliki]` marker.
- Rewinding a message in the GUI restores its attachments as real files in the
  composer instead of leaving only their names in the text.

## TUI

- Colours use the same hex palette as the GUI (accent, background and
  surfaces), and the header has its own background bar.

## Compaction

- The compaction summary keeps a short block with the three most recent user
  messages verbatim, so the agent does not lose the latest instructions.

## Verification

The full Go suite passed on Windows, followed by all 318 UI tests, including a
new rewind test that checks restored attachments. Image input was tested live
against the official Anthropic API and with a free OpenCode Zen model after a
rewind; the model answered from the image without tool calls. Android ARM64 is
cross-compiled; physical-device Termux testing remains pending.

Portable bundles include both executables and public application assets. Keep
your existing `supercli-data/` folder when updating.
