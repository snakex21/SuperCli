# SuperCli 1.0.2

This maintenance release reduces unnecessary context, allocations and rendering work, and adds on-demand screenshots and local media previews. GUI and TUI continue to share the same agent engine for local and cloud models.

- **Screen and media tools:** `send_screenshot` can capture the screen or clipboard, save the image in the portable snapshots folder, and optionally attach it to the model. A screenshot request exposes its schema immediately, avoiding an extra discovery round and mistaken refusals about missing desktop access. `attach:false` saves and presents the screenshot without sending pixels. `show_media` presents a local image, MP4/WebM video or MP3/WAV/Ogg audio file using small metadata. GUI previews load on demand; audio/video do not autoplay. TUI returns the file path. Capturing and displaying files do not require an image-generation model. Understanding an image requires a vision-capable model; image/video generation is not included in this release.
- **GUI responsiveness:** reuse completed reasoning sections during answer streaming, render folded history and tool output on demand, preserve active queue transitions, and avoid unnecessary full-transcript work. Session titles use meaningful conversation text instead of generic completion reports. The built-in site preview can be reset or resized, and opening links in the system browser works through the native Windows association.
- **TUI:** reuse unchanged transcript sections and dashboard hints, preserve queued work and drafts, and improve preview navigation and provider setup. Terminal output remains text-based.
- **Less input and repeated work:** return bounded, grouped search results with usable source context; keep concise HTML results; request only selected PDF pages or XLSX sheets; reuse parsed tool arguments and verified command evidence; avoid retaining redundant tool schemas and image hashes. Failed commands and ambiguous patch anchors receive more precise handling.
- **Memory and uploads:** release decoded session rows as the model context is reconstructed, avoid redundant image hashing, and stream multipart attachments directly to their staging folder instead of retaining large buffers and spilling into OS temp. A 9 MiB upload allocated about 54 KB instead of 33.7 MB in the measured handler benchmark. This does not imply that the WebView2 runtime uses that little memory.
- **Portable data and providers:** keep screenshot history addressable after moving the application folder, exclude portable runtime data from workspace checkpoints, improve free-provider catalog snapshots, and share the expanded provider choices between GUI and TUI. Existing OpenCode Zen behavior is preserved.

## Downloads and updates

Each portable ZIP includes both `supercli` (TUI/CLI) and `supercli-web` (GUI), documentation in 27 languages and the built-in skill pack. Choose Windows x64, Linux x64/ARM64, or macOS Intel/Apple Silicon. Preserve executable permissions when extracting on Linux/macOS; if needed, run `chmod +x supercli supercli-web` in the extracted folder.

GUI About and TUI `/update check` can detect this stable release. The matching bundles are verified using `supercli-update.json` and `SHA256SUMS`. Existing portable configuration and history are preserved during updates; restart after installation.

Windows native screen capture was tested at 3840 × 2160. Linux/macOS capture paths were compiled and covered by unit fixtures; Linux needs an installed `grim` or `gnome-screenshot` helper, and macOS screen-capture permission may be required. Native desktop behavior on those platforms was not tested here.
