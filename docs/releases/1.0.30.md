# SuperCli 1.0.30

Fixes for the findings of an internal audit: fewer false name-check hints,
sturdier provider streams, a guard against runaway tool-call arguments,
compaction that no longer wedges long sessions, safer file writes on Windows,
and terminal and web GUI usability fixes. Polish notes follow the English ones.

## Before updating

- Back up your portable `supercli-data` directory and close other running
  copies before installing. The updater replaces the two executables, not
  private data, and a manual restart is required afterward.
- No configuration changes are required. Two new optional settings are
  described below (`SUPERCLI_LLM_MAX_TOKENS` now also on the Responses API,
  `SUPERCLI_LLM_TOOL_STREAM_TIMEOUT`).

## Name check: no more false "not found" hints

The name check (1.0.28) tells the model which names from your request do not
exist in the workspace. In the audit it also flagged names that were never
meant to exist there, and the model then refused correct work: `ValueError`
(a Python built-in), `polandcentral` in "change the region from `westeurope`
to `polandcentral`" (the new value), and `path:line` (an output format).

The check now skips language built-ins and standard-library names, existing
git branches and tags, `main`/`master` and slash names in a sentence about
branches or rebases, output-format placeholders such as `path:line`, the new
value in "change/set/raise … to X" and "rename … to X", and the first name of
a list item under a "split … into:" heading. The hint is also softer: a new
value is simply used or created. A name that your request treats as already
existing (a setting, function, file or flag) is still reported instead of
being invented or swapped for a look-alike.

## Provider streams

- A connection that is reset or closed, or ends early, before anything was
  shown is now retried on both the Chat Completions and the Responses API.
- A stream that goes silent ends with "no data from provider for Ns (idle
  timeout)" and is retried, instead of a vague cancellation.
- On the Responses API an HTTP error keeps its status code and `Retry-After`,
  so `fallback_models` cooldowns work there too.
- A single stream line may now be longer than 1 MiB (a large tool call on the
  Responses API no longer fails with "token too long").

## Runaway tool-call arguments

In 1.0.28 a model once streamed the same block of text into a tool call's
arguments until it hit the provider's output limit. Now:

- Arguments are stopped at 256 KiB, or earlier when the last 16 KiB are a
  loop. The model is asked to try again within the existing bounded retry.
  The rejected text is not kept in the conversation history; a short stub is
  stored instead. Very regular data, such as a long array of zeros, can also
  trip this; the model is then asked to split the write.
- Receiving one tool call may take at most 10 minutes
  (`SUPERCLI_LLM_TOOL_STREAM_TIMEOUT`, seconds, 0 = off), with a progress
  notice every 30 s while a long call arrives.
- Cloud endpoints get an output cap by default (32000 tokens, 64000 for
  reasoning models) when `SUPERCLI_LLM_MAX_TOKENS` is not set. If a provider
  rejects it, the request is repeated once with the provider's limit or
  without the cap. Local servers, OpenCode Zen and the ChatGPT Codex backend
  are unchanged. `SUPERCLI_LLM_MAX_TOKENS` now also applies to the Responses
  API.
- Tokens of a cancelled or failed stream now count in usage and cost (marked
  as estimated when the provider sent no usage).

## Long sessions and compaction

Compaction used to carry every earlier request of the session along word for
word. With long requests in a small context window, a session could get
stuck: every following turn failed. The carried requests are now limited to
1/8 of the window: the newest one stays word for word when it fits, older ones
are shortened to their beginning and end with a visible marker, and the
oldest ones are dropped first if needed. `docs/architecture.md` now states the
real trigger (window minus a 10% reserve, about 90%), not 80%.

## Files and links on Windows

- `write_file`, `patch_file`, undo and the GUI file editor now write through a
  temporary file and a rename, like `edit_files`. A workspace file that is a
  hard link to a file outside the workspace (for example a pnpm package linked
  into the global store) gets its own copy; the outside file never changes.
- Reserved device names (`CON`, `NUL`, `COM1`, `LPT1`, …, with any extension,
  also in a sub-folder such as `sub\nul.txt`) are refused as paths.
- `read_zip` may extract into a junction inside the workspace or through one.
  All protections against unsafe entry names stay.
- Junctions and dangling symlinks inside the workspace remain deliberate
  grants. `docs/configuration.md` has a new section "Links inside the
  workspace".

## Terminal interface (TUI)

- While SuperCli waits to retry a provider, the status line shows the retry
  state instead of the generic working label, and one outage is one line in
  the transcript (it used to add a line per attempt).
- The raw key `project.stopRun` no longer appears; it is translated in all 27
  languages.
- `/diff`: the header is translated and has no raw Markdown, and the "more
  lines" count is the real number of hidden lines (it always said 20).
- Narrow terminals: the approval key hint (y/n/a) stays visible, the main
  screen fits very small windows, and slash commands no longer make the frame
  one row taller than the terminal.

## Web GUI

- After you answer an approval card, keyboard focus returns to the message
  box.
- The control panel is a proper dialog: focus moves into it and back to the
  button that opened it, and Esc in a settings field only cancels that edit
  (a second Esc closes the panel).
- At 560 px and narrower, the reasoning button keeps its label and a 44 px
  touch target, Send stays on the attachment row, and at 360 px the approval
  card opens with its title visible.

## Measurements

gpt-6-luna, reasoning effort low, 3 repeats per suite, 1.0.29 vs 1.0.30:

| suite | 1.0.29 pass rate / score | 1.0.30 pass rate / score | cost per repeat |
|---|---|---|---|
| v2 (18 tasks) | 87.0% / 0.929 | 87.0% / 0.931 | $0.0361 → $0.0375 |
| ho2 (10 tasks) | 93.3% / 0.993 | 90.0% / 0.990 | $0.0150 → $0.0152 |
| ho3 (13 tasks) | 82.1% / 0.912 | 100% / 1.000 | $0.0230 → $0.0231 |
| v1 (26 tasks, once) | — | 26/26 | — |

ho3 was written by the audit that found these problems, so it is no longer a
blind test; v2 and ho2 are the main evidence. The ho2 difference is one task
(`ho2-js-refactor-options`) that fails on the same grader check in both
versions. The ho2 missing-name honesty tasks still pass (the environment
variable task: 20 of 21 runs with 1.0.30, 9 of 9 with 1.0.29).

# SuperCli 1.0.30 (PL)

Poprawki po wewnętrznym audycie: mniej fałszywych podpowiedzi sprawdzania
nazw, odporniejsze strumienie od dostawców, ochrona przed zapętlonymi
argumentami wywołań narzędzi, kompaktowanie, które nie blokuje długich sesji,
bezpieczniejszy zapis plików w Windows oraz poprawki interfejsu terminalowego
i GUI.

## Przed aktualizacją

- Zrób kopię przenośnego katalogu `supercli-data` i zamknij inne uruchomione
  kopie. Aktualizacja podmienia dwa pliki wykonywalne, nie dane prywatne. Po
  instalacji uruchom program ponownie ręcznie.
- Konfiguracja nie wymaga zmian. Dwa nowe, opcjonalne ustawienia są opisane
  niżej (`SUPERCLI_LLM_MAX_TOKENS` teraz także w Responses API,
  `SUPERCLI_LLM_TOOL_STREAM_TIMEOUT`).

## Sprawdzanie nazw bez fałszywych „nie znaleziono”

Sprawdzanie nazw (1.0.28) mówi modelowi, których nazw z polecenia nie ma w
projekcie. W audycie oznaczało też nazwy, których z założenia tam nie ma, a
model odmawiał wtedy poprawnej pracy: `ValueError` (wbudowany wyjątek
Pythona), `polandcentral` w „zmień region z `westeurope` na `polandcentral`”
(nowa wartość) i `path:line` (format wyniku).

Teraz pomijane są: nazwy wbudowane języków i bibliotek standardowych,
istniejące gałęzie i tagi gita, `main`/`master` oraz nazwy z ukośnikiem w
zdaniu o gałęziach albo rebase, wzorce formatu typu `path:line`, nowa wartość
w „zmień/ustaw/podnieś … na X” i „przemianuj … na X” oraz pierwsza nazwa
punktu listy pod nagłówkiem „podziel … na:”. Podpowiedź jest też łagodniejsza:
nową wartość model po prostu używa albo tworzy. Nazwa, którą polecenie traktuje
jako już istniejącą (ustawienie, funkcja, plik, flaga), nadal jest zgłaszana,
zamiast być wymyślona albo zamieniona na podobną.

## Strumienie od dostawców

- Połączenie zerwane, zamknięte albo urwane, zanim cokolwiek się pokazało,
  jest teraz ponawiane w Chat Completions i w Responses API.
- Strumień, który milknie, kończy się komunikatem „no data from provider for
  Ns (idle timeout)” i jest ponawiany, zamiast niejasnego anulowania.
- W Responses API błąd HTTP zachowuje kod i `Retry-After`, więc przerwy
  `fallback_models` działają także tam.
- Pojedyncza linia strumienia może mieć ponad 1 MiB (duże wywołanie narzędzia
  w Responses API nie kończy się już błędem „token too long”).

## Zapętlone argumenty wywołań narzędzi

W 1.0.28 model raz wysyłał ten sam fragment tekstu w argumentach wywołania
narzędzia, aż doszedł do limitu wyjścia dostawcy. Teraz:

- Argumenty są przerywane przy 256 KiB albo wcześniej, gdy ostatnie 16 KiB to
  pętla. Model dostaje prośbę o ponowienie w ramach istniejącego, ograniczonego
  ponawiania. Odrzucony tekst nie zostaje w historii rozmowy; zapisywany jest
  krótki zamiennik. Bardzo regularne dane, np. długa tablica zer, też mogą to
  wywołać; model dostaje wtedy prośbę o podzielenie zapisu.
- Odbiór jednego wywołania narzędzia trwa najwyżej 10 minut
  (`SUPERCLI_LLM_TOOL_STREAM_TIMEOUT`, w sekundach, 0 = wyłączone), z
  komunikatem o postępie co 30 s przy długim wywołaniu.
- Dostawcy w chmurze dostają domyślny limit wyjścia (32000 tokenów, 64000 dla
  modeli rozumujących), gdy `SUPERCLI_LLM_MAX_TOKENS` nie jest ustawione. Jeśli
  dostawca go odrzuci, zapytanie jest powtarzane raz z jego limitem albo bez
  limitu. Serwery lokalne, OpenCode Zen i backend ChatGPT Codex działają bez
  zmian. `SUPERCLI_LLM_MAX_TOKENS` działa teraz także w Responses API.
- Tokeny anulowanego albo przerwanego strumienia są liczone w zużyciu i
  koszcie (oznaczone jako szacunek, gdy dostawca nie podał zużycia).

## Długie sesje i kompaktowanie

Kompaktowanie przenosiło dosłownie każde wcześniejsze polecenie z sesji. Przy
długich poleceniach i małym oknie kontekstu sesja mogła się zablokować: każda
kolejna tura kończyła się błędem. Przenoszone polecenia mają teraz limit 1/8
okna: najnowsze zostaje dosłownie, jeśli się mieści, starsze są skracane do
początku i końca z widocznym znacznikiem, a w razie potrzeby najstarsze są
pomijane. `docs/architecture.md` podaje teraz prawdziwy próg (okno minus 10%
rezerwy, około 90%), a nie 80%.

## Pliki i dowiązania w Windows

- `write_file`, `patch_file`, cofanie zmian i edytor plików w GUI zapisują
  teraz przez plik tymczasowy i zmianę nazwy, jak `edit_files`. Plik w
  projekcie, który jest twardym dowiązaniem do pliku poza projektem (np.
  pakiet pnpm połączony z globalnym magazynem), dostaje własną kopię; plik na
  zewnątrz nigdy się nie zmienia.
- Zarezerwowane nazwy urządzeń (`CON`, `NUL`, `COM1`, `LPT1`, …, z dowolnym
  rozszerzeniem, także w podfolderze, np. `sub\nul.txt`) są odrzucane jako
  ścieżki.
- `read_zip` może rozpakowywać do junction w projekcie albo przez nie.
  Wszystkie zabezpieczenia przed niebezpiecznymi nazwami wpisów zostają.
- Junction i wiszące dowiązania symboliczne w projekcie nadal są celowym
  udostępnieniem. `docs/configuration.md` ma nową sekcję „Links inside the
  workspace”.

## Interfejs terminalowy (TUI)

- Gdy SuperCli czeka na ponowienie zapytania do dostawcy, linia stanu pokazuje
  stan ponawiania zamiast ogólnego „pracuję”, a jedna awaria to jedna linia w
  rozmowie (wcześniej każda próba dodawała linię).
- Nie pojawia się już surowy klucz `project.stopRun`; jest przetłumaczony we
  wszystkich 27 językach.
- `/diff`: nagłówek jest przetłumaczony i bez surowego Markdownu, a liczba
  ukrytych wierszy jest prawdziwa (wcześniej zawsze 20).
- Wąskie terminale: podpowiedź klawiszy zatwierdzenia (y/n/a) jest widoczna,
  ekran główny mieści się w bardzo małych oknach, a polecenia z ukośnikiem nie
  powiększają już ramki o jeden wiersz ponad terminal.

## GUI

- Po odpowiedzi na kartę zatwierdzenia fokus wraca do pola wiadomości.
- Panel sterowania jest prawdziwym oknem dialogowym: fokus przechodzi do
  niego i wraca do przycisku, który go otworzył, a Esc w polu ustawień tylko
  anuluje tę edycję (drugi Esc zamyka panel).
- Przy szerokości 560 px i mniejszej przycisk rozumowania zachowuje etykietę i
  pole dotyku 44 px, Wyślij zostaje w rzędzie załączników, a przy 360 px karta
  zatwierdzenia otwiera się z widocznym tytułem.
