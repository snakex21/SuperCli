# SuperCli 1.0.21

Web tools that read what is actually on the page: clean main-content
extraction, PDF and Polish-charset support, paging, a headless browser tool,
multi-query and optional provider-hosted search. Everything works with local
models; nothing new requires an API key.

## Before updating

- Back up your portable `supercli-data` directory and close other running copies
  before installing. The updater replaces the two executables, not private data,
  and a manual restart is required afterward.

## Reading web pages (`web_fetch`)

- **Main content first**: HTML is parsed and menus, footers, sidebars, cookie
  banners, language lists and link-heavy navigation are dropped, so the model
  sees the article instead of the site chrome. Headings, lists and code blocks
  are kept as Markdown.
- **Links and pagination**: next/previous links are listed even when they sit
  inside page navigation, plus the first page links; `mode=links` lists all.
- **Structured data**: schema.org facts such as product price, currency,
  availability and publication dates are shown with the page.
- **PDF** files are read as text (up to 20 MB) with correct word spacing.
- **Charsets**: ISO-8859-2, windows-1250 and UTF-16 pages are decoded instead of
  being rejected as binary.
- **Paging**: long pages end with an `offset` to continue; continuation and
  `mode=links` reuse a 10-minute page cache instead of fetching again. Missing
  pages (404/410) are cached briefly.
- **Sized to the model**: the default window is about 7% of the active model's
  context window (3,000 to 14,000 characters), so 8k to 32k local models are
  not flooded and large models get a useful window without a truncated preview.
- **Clear notes** for JavaScript-only pages (inline script data is shown),
  bot-protection/CAPTCHA pages, login walls and slow servers (the received part
  is kept).
- **Prompt-injection hygiene**: everything that comes from the page is wrapped
  in markers labelling it as untrusted data.

## Browser (`browser`)

- New discoverable tool driving a headless Chrome or Edge: `open`, `click`,
  `type`, `read`, `back`, `close`. Results show the rendered page text and the
  visible interactive elements with stable refs such as `[e3]`.
- All browser traffic goes through a local proxy that refuses private and
  loopback addresses (including after redirects and DNS changes).
- The browser uses a temporary profile, closes after 5 idle minutes and when
  SuperCli exits; on Windows it also runs in a job object so it cannot outlive
  a crashed process. Available in the TUI, batch mode and the GUI.
- `tool_search` activates a tool asked for as "browser tool" or "use the
  browser" in one call.

## Search (`web_search`, `web_lookup`)

- **Several queries in one call**: `queries` runs up to 3 extra related
  searches in parallel; results stay labelled per query without duplicate URLs.
- **Exa** engine (`engine = "exa"`, `EXA_API_KEY`).
- **Optional provider-hosted search**, off by default: `[web_search] hosted =
  "openai"`, `"xai"` or `"auto"` answers searches with the provider's own web
  search tool and falls back to the local engines on any error. It is opt-in
  because hosted searches are billed and send the query to the provider. See
  `docs/configuration.md`.
- Tool descriptions steer models to read a given URL with `web_fetch` alone
  instead of searching in parallel.

## Tested

- Scenario set run through the real agent loop with gpt-5.4-mini and with local
  models in LM Studio at 32k context (Qwen 3.6 35B-A3B and a dense Qwen 27B
  solved all 9 scenarios; Qwen 3.5 9B, Qwen 3.5 35B-A3B and LFM 2.5 24B-A2B
  solved most), covering search, summaries of Polish pages, shop price
  comparison, a JavaScript page, a PDF, a 404, a slow server and click-through
  navigation.
