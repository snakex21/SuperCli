# SuperCli 1.0.27

Harder multi-file tasks now get finished instead of abandoned halfway:
a new `edit_files` tool makes one change in many files in a single call, a
missing file no longer sinks the rest of a request, and long single turns
prune their context less often. Polish notes follow the English ones.

## Before updating

- Back up your portable `supercli-data` directory and close other running
  copies before installing. The updater replaces the two executables, not
  private data, and a manual restart is required afterward.
- No configuration changes are required.

## edit_files: one change, many files

`edit_files` applies one edit to every file that matches a glob: replace text
(literal, whole-identifier or regex), or prepend/append text such as a license
header or an import.

- Filters: an `exclude` glob, plus `skip_if_matches` / `only_if_matches`
  regular expressions on file content (for example, skip generated files or
  files that already have a header).
- `dry_run` lists the files that would change and previews the first one.
- The result lists changed, skipped and unmatched files. After a replace it
  also reports how many matches are left, so completeness is checked by the
  same call.
- CRLF files stay CRLF and a UTF-8 BOM stays first. Each file is written
  atomically. A file that changed while the call was running is left alone.
- It is a regular file mutation: undo checkpoint (scoped to the folder),
  code-intelligence diagnostics for the changed files, and the approval gate.
  Edits inside the workspace are not gated, the same as `patch_file`. An edit
  of more than 200 files, or one rooted outside the workspace, asks for
  approval first.

## Finishing what is possible

- The system prompt no longer says a missing file stops the request. The
  agent now does every other part, says what is missing and asks, and still
  never invents or substitutes the missing target.
- Completion check: when the final answer itself says part of the work is not
  done ("I did not finish", "I haven't changed any files"), the agent gets
  one more pass per request to do the remaining possible parts and report
  only what is truly blocked. It does not run otherwise.
  `completion_check = false` turns it off.
- The prompt asks for a search for leftovers (an old name, files still
  missing a change) after multi-file work.

## Context pruning on long single turns

When a long single turn (6 or more tool results) has to prune old tool
results, the prune now goes down to 45 % of the window instead of stopping
just under the trigger. Prunes therefore happen less often, and each one
invalidates the provider's prompt cache only once. The two newest completed
steps and the current step are always kept. Earlier conversation turns keep
their protected tail as before.

On the two long 16k-window tasks of the v1 suite, compared with 1.0.26:

| | 1.0.26 (3 runs) | 1.0.27 (9 runs) |
|---|---|---|
| long-multi-fix: prunes per run | 3.0 | 1.7 |
| long-multi-fix: cache share | 0.766 | 0.808 |
| long-multi-fix: cost per run | $0.0049 | $0.0039 |
| long-inventory: cache share | 0.676 | 0.719 |
| long-inventory: tasks passed | 2/3 | 7/9 |

## Measurements

Cloud evaluation with gpt-6-luna at reasoning effort low, 3 repeats per
suite (mean ± standard deviation):

| suite | 1.0.26 | 1.0.27 |
|---|---|---|
| v1, 26 tasks: pass rate | 98.7 ± 2.2 % | 98.7 ± 2.2 % |
| v2, 18 harder tasks: pass rate | 59.3 ± 6.4 % | 70.4 ± 3.2 % |
| held-out, 7 new tasks: pass rate | 57.1 ± 0.0 % | 61.9 ± 8.2 % |
| v1 cost per run | $0.0239 | $0.0227 |
| v2 cost per run | $0.0391 | $0.0356 |
| held-out cost per run | $0.0188 | $0.0223 |

- v2 tasks that improved: `v2-go-batch-spdx` 0/3 → 3/3 (with `edit_files`),
  `v2-honesty-partial` 2/3 → 3/3, `v2-py-config-migration` 2/3 → 3/3, and
  `v2-go-flaky-tests` and `v2-py-misleading-trace` by one run each.
  `v2-ts-honesty-symbol` dropped by one run (2/3 → 1/3).
- Still failing 0/3: `v2-ts-rename-field` (the model leaves a `userId`
  parameter in `account.ts`), `v2-parallel-service-audit` (the audit report
  is not exact) and `v2-big-log-incident`.
- The held-out suite (multi-file, partial-information and long-context tasks)
  was written for this release and never used to tune it. It is new in
  `test/go/eval/agent-suite-heldout.json`. The gain there,
  `ho-ts-deprecate-raw-sql` 0/3 → 1/3, is within the noise. Both honesty
  tasks in it still fail: the model invents a missing config key, or uses a
  similarly named function instead of reporting the requested one as missing.
  Held-out cost went up 19 % because the deprecation task now does more of
  the work.
- Dropped before release: a second completion-check trigger that sent every
  request that edited 3 or more files back for a leftovers search. In an
  ablation on v2 it scored 75.9 ± 3.2 % with the trigger and 70.4 ± 8.5 %
  without, which is within the noise, and it cost 15-28 % more per v2 run.
  On the held-out suite the build with it scored 76.2 ± 8.2 %. That number
  came in after the decision and was not used to make it.

# SuperCli 1.0.27 (PL)

Trudniejsze zadania obejmujące wiele plików są teraz kończone, a nie
porzucane w połowie. Nowe narzędzie `edit_files` wprowadza jedną zmianę w
wielu plikach jednym wywołaniem. Brakujący plik nie blokuje już reszty
polecenia. Długie pojedyncze tury rzadziej przycinają kontekst.

## Przed aktualizacją

- Zrób kopię przenośnego katalogu `supercli-data` i zamknij inne uruchomione
  kopie. Aktualizacja podmienia dwa pliki wykonywalne, nie dane prywatne. Po
  instalacji uruchom program ponownie ręcznie.
- Konfiguracja nie wymaga zmian.

## edit_files: jedna zmiana, wiele plików

`edit_files` wprowadza jedną edycję we wszystkich plikach pasujących do wzorca
glob. Może zastąpić tekst (dosłownie, całe identyfikatory albo wyrażenie
regularne) albo dopisać tekst na początku lub końcu pliku, np. nagłówek
licencji albo import.

- Filtry: wzorzec `exclude` oraz wyrażenia regularne `skip_if_matches` i
  `only_if_matches` sprawdzane na treści pliku (np. pomiń pliki generowane
  albo takie, które już mają nagłówek).
- `dry_run` pokazuje listę plików, które by się zmieniły, oraz podgląd
  pierwszego z nich.
- Wynik wymienia pliki zmienione, pominięte i niepasujące. Po zamianie podaje
  też, ile wystąpień zostało, więc to samo wywołanie sprawdza, czy zmiana
  objęła wszystko.
- Pliki z końcami linii CRLF zostają w CRLF, a znacznik BOM UTF-8 zostaje na
  początku. Każdy plik jest zapisywany atomowo. Plik zmieniony w trakcie
  działania narzędzia nie jest nadpisywany.
- To zwykła zmiana plików: punkt cofania (ograniczony do folderu),
  diagnostyka analizy kodu dla zmienionych plików i bramka zgody. Edycje w
  obrębie workspace'u nie wymagają zgody, tak jak `patch_file`. Edycja ponad
  200 plików albo w folderze poza workspace'em najpierw prosi o zgodę.

## Zrób, co się da

- Prompt systemowy nie mówi już, że brakujący plik zatrzymuje polecenie.
  Agent wykonuje wszystkie pozostałe części, mówi, czego brakuje, i pyta. Nadal
  nigdy nie wymyśla ani nie podmienia brakującego celu.
- Kontrola ukończenia: gdy końcowa odpowiedź sama przyznaje, że część pracy
  nie została zrobiona („nie dokończyłem”, „nie zmieniłem żadnego pliku”),
  agent dostaje jedno dodatkowe podejście na polecenie. Ma w nim zrobić
  pozostałe możliwe części i zgłosić tylko to, co naprawdę jest zablokowane.
  W innych przypadkach kontrola się nie uruchamia. `completion_check = false`
  ją wyłącza.
- Prompt prosi, by po pracy na wielu plikach wyszukać pozostałości (starą
  nazwę, pliki bez zmiany).

## Przycinanie kontekstu w długich pojedynczych turach

Gdy długa pojedyncza tura (6 lub więcej wyników narzędzi) musi przyciąć stare
wyniki narzędzi, przycinanie schodzi teraz do 45% okna, zamiast zatrzymywać
się tuż pod progiem. Dzięki temu przycięć jest mniej, a każde z nich tylko raz
unieważnia cache promptu u dostawcy. Dwa najnowsze zakończone kroki i bieżący
krok są zawsze zachowane. Wcześniejsze tury rozmowy zachowują chroniony ogon
jak dotąd.

Na dwóch długich zadaniach z oknem 16k w zestawie v1, w porównaniu z 1.0.26:

| | 1.0.26 (3 przebiegi) | 1.0.27 (9 przebiegów) |
|---|---|---|
| long-multi-fix: przycięcia na przebieg | 3,0 | 1,7 |
| long-multi-fix: udział cache | 0,766 | 0,808 |
| long-multi-fix: koszt przebiegu | 0,0049 $ | 0,0039 $ |
| long-inventory: udział cache | 0,676 | 0,719 |
| long-inventory: zaliczone | 2/3 | 7/9 |

## Pomiary

Ewaluacja w chmurze, gpt-6-luna z reasoning effort low, 3 powtórzenia na
zestaw (średnia ± odchylenie standardowe):

| zestaw | 1.0.26 | 1.0.27 |
|---|---|---|
| v1, 26 zadań: zaliczone | 98,7 ± 2,2% | 98,7 ± 2,2% |
| v2, 18 trudniejszych zadań: zaliczone | 59,3 ± 6,4% | 70,4 ± 3,2% |
| held-out, 7 nowych zadań: zaliczone | 57,1 ± 0,0% | 61,9 ± 8,2% |
| koszt przebiegu v1 | 0,0239 $ | 0,0227 $ |
| koszt przebiegu v2 | 0,0391 $ | 0,0356 $ |
| koszt przebiegu held-out | 0,0188 $ | 0,0223 $ |

- Poprawione zadania v2: `v2-go-batch-spdx` 0/3 → 3/3 (dzięki `edit_files`),
  `v2-honesty-partial` 2/3 → 3/3, `v2-py-config-migration` 2/3 → 3/3, oraz
  `v2-go-flaky-tests` i `v2-py-misleading-trace` o jeden przebieg każde.
  `v2-ts-honesty-symbol` spadło o jeden przebieg (2/3 → 1/3).
- Nadal 0/3: `v2-ts-rename-field` (model zostawia parametr `userId` w
  `account.ts`), `v2-parallel-service-audit` (raport audytu nie jest
  dokładny) i `v2-big-log-incident`.
- Zestaw held-out (zadania na wielu plikach, z niepełną informacją i z długim
  kontekstem) powstał na potrzeby tego wydania i nie był używany do jego
  strojenia. Jest nowy w `test/go/eval/agent-suite-heldout.json`. Zysk na nim,
  `ho-ts-deprecate-raw-sql` 0/3 → 1/3, mieści się w szumie. Oba zadania
  dotyczące uczciwości nadal nie przechodzą: model wymyśla brakujący klucz
  konfiguracji albo używa funkcji o podobnej nazwie, zamiast zgłosić, że
  żądanej nie ma. Koszt held-out wzrósł o 19%, bo zadanie z oznaczaniem
  funkcji jako przestarzałych wykonuje teraz więcej pracy.
- Usunięte przed wydaniem: drugi wyzwalacz kontroli ukończenia, który każde
  polecenie zmieniające 3 lub więcej plików odsyłał do szukania pozostałości.
  W ablacji na v2 dawał 75,9 ± 3,2% z wyzwalaczem i 70,4 ± 8,5% bez niego, co
  mieści się w szumie, a kosztował 15-28% więcej na przebieg v2. Na zestawie
  held-out kompilacja z nim uzyskała 76,2 ± 8,2%. Ten wynik przyszedł po
  podjęciu decyzji i nie był do niej użyty.
