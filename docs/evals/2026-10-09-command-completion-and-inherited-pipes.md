# Command completion, Stop and inherited Git output pipes — 2026-10-09

The observed resumed Haiku session persisted a native cmd IF EXIST / echo tool call but no tool result before window closure. An independent native Windows regression reproduced an indefinite wait in checkpoint Git output handling: the OS process had exited while a stdout/stderr writer duplicated outside its process scope remained open. Both ordinary completion and cancellation hung in all four baseline cases. This establishes a real lifecycle bug; it does not establish that inherited handles were the sole cause of the observed user session.

Checkpoint Git factories now bound output draining after native exit. Manual readers own their stdout pipes, wait for native exit concurrently, close the reader on context cancellation, join their one waiter and fail closed on incomplete Git protocol. Coverage includes workspace enumeration, narrow tree parsing, blob restore, retention inventory and Git initialization/buffered output. There is no added command runtime cap; long downloads and live producers can continue. The exceptional drain grace is one second, and separate stdout/stderr stages can each incur a grace period for retained external handles.

Baseline: four native held-pipe cases failed (14.974 s total) because wait/scan did not return. After the fix, all four passed alongside the three remaining manual readers, restore staging cleanup, exact output exceeding 2 MiB including UTF-8/NUL and final stdout/stderr bytes, a cancelled live producer and a producer intentionally living longer than the drain grace (14.693 s focused package result). The live cancel case completed in about 30 ms; delayed live exit continued about 1.54 s, showing that the drain grace is not a runtime deadline.

Actual HTTP GUI regressions run the production composer submit listener, SSE reader, tool-row renderer and cleanup. With native cmd success, native curl downloading/validating an owned GIF and native cmd exit 7, every tool received exactly one result, lost its running class and clock, the stream completed, all run timers stopped, backend activeWork became false and a second prompt reached the same session without rerunning the command. The GIF is hosted on an owned loopback server for deterministic network behavior; this test does not assert the current availability or authentication of Tenor.

Additional existing regressions abort a live curl against a blocked owned endpoint, verify a durable completion receipt and send the next prompt using actual HTTP. Receipt latency in the focused run was about 404 ms. GUI Stop covers both a running command and a checkpoint store held before admission. All 235 production JS/DOM tests passed with zero skips. These checks exercise actual processes, transport and application state; they do not emulate native window closing or WebView paint.
